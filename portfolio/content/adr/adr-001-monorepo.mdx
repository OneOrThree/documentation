## 맥락

API 서버, 인코딩 워커, 웹, 문서 사이트가 각각 배포된다. 초기에는 네 개의 저장소로 시작했는데, 두 달 만에 같은 DTO가 세 벌 생겼고 그중 하나만 필드가 추가된 상태로 배포된 적이 있다. 컴파일은 저장소마다 따로 통과했으므로 아무도 알아채지 못했다.

## 선택지

| 선택지 | 계약 변경 감지 | 배포 독립성 | CI 비용 |
| --- | --- | --- | --- |
| 저장소 4개 유지 | 런타임에만 | 높음 | 낮음 |
| 모노레포 + 단일 배포 | 컴파일 타임 | 없음 | 낮음 |
| 모노레포 + 배포 단위 분리 | 컴파일 타임 | 높음 | 중간 |

## 결정

**모노레포를 쓰되 배포 단위는 나눈다.** 공유 타입은 `packages/contracts` 하나에만 두고, 각 서비스는 거기에 의존한다. CI는 변경된 경로에 해당하는 파이프라인만 돌린다.

```bash
# 변경된 워크스페이스만 빌드
npm run build --workspaces --if-present
```

## 근거

- 계약이 깨지면 **머지 전에** 빨간불이 뜬다. 위 사고의 재발 경로가 막힌다.
- 배포는 여전히 서비스별이라, 워커 배포가 API를 재시작시키지 않는다.
- CI 비용 증가는 경로 필터로 상쇄된다. 실측 결과 평균 CI 시간은 4분 10초 → 4분 40초로, 30초 늘었다.

## 영향

- 새 서비스를 추가할 때 저장소를 만들지 않는다. `apps/` 아래 디렉터리 하나가 전부다.
- 외부 공개가 필요한 패키지가 생기면 이 결정을 다시 봐야 한다. 지금은 없다.
