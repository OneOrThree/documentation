## 결정

- 휴식(`PAUSED`) 중에도 이모티콘을 보낼 수 있다. TTL은 **3초**, 빈도는 **창당 1건**이다. 초기 LLD의 ACTIVE 전용 문장은 9월 20일 정책 결정으로 뒤집혔다.
- 실시간 presence의 존재만으로 SEND·SUBSCRIBE·수신 자격을 승인하지 않는다. Data의 SET/DEL이 best-effort이므로, 키가 없을 때 정상 주민을 배제하고 키가 남을 때 종료 주민을 허용할 수 있다.
- 응원 수신자는 이미 발신 검증에 사용하던 Data API `focus-members` 조회의 **현재 진행 중 주민 집합**으로 정한다. 별도 상류 조회를 구독자마다 늘리지 않는다. 같은 이벤트의 중복은 `eventId`로 막는다.

## 왜 바뀌었나

구현 중에는 "presence 키의 수명이 곧 참가 자격"이라는 판단이 나왔지만, 서버 계약은 presence를 비권위 사본으로 정의했다. 리뷰에서 그 전제를 뒤집고 현재 세션 정본을 사용했다. SEND만 막고 SUBSCRIBE 경로를 빼먹은 점도 같은 검토에서 발견됐다. 수신 집합을 STOMP 커스텀 헤더에 실은 첫 배선은 브로커가 헤더를 재생성하면서 값을 버려 전원 차단됐고, `eventId` 기반 프로세스 내 보관으로 교체했다.

## 전달 방식과 한계

9월 19일에는 Data API의 실시간 사건 전달을 **HTTP 기본, Kafka 선택**으로 정했다. 두 입구는 같은 처리기로 들어가 `eventId`로 중복을 제거한다. 당시 처음 열린 경로는 사건을 받아 200을 반환했지만 STOMP 발행은 아직 열지 않았으므로, 수신 200을 앱 실시간 반영 완료로 읽으면 안 된다. 앱은 스냅샷 조회로 복구한다.
