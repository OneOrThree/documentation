## 맥락

i18n(internationalization, 다국어화)은 글로벌 출시 준비 에픽(GROMO-1672)의 기술 선행 작업이었다. 앱 문구가 전부 코드에 직접 박힌 한국어 리터럴이라 다른 언어를 붙일 자리가 없었다.

범위는 ko(정본)·en·ja·zh-Hant(번체, 대만·홍콩) 4개 언어다. 간체(중국 본토)는 지원하지 않고 영어로 떨어진다. 기기 언어는 `expo-localization`으로 읽고, 앱 안 설정(전체 탭 → 언어)으로 덮어쓸 수 있다. 설정값은 기기에 귀속된 AsyncStorage에 두어 로그아웃·탈퇴로 지워지지 않는다.

문구를 키로 옮기는 것 자체는 기계적인 작업이다. 설계가 필요했던 것은 다섯 질문이다.

1. 번역이 없는 키는 어느 언어로 떨어지나.
2. 앱 안에서 언어를 바꾸면 이미 그려진 화면을 어떻게 다시 그리나.
3. 준비 시험 이름은 번역하는가.
4. 앱 밖 표면(집중 가림막, 잠금화면 Live Activity, 위젯, 권한 팝업)은 누구의 언어를 따르나.
5. 언어를 서버에 보내지 않는 구버전 앱 사용자에게 서버 푸시는 어떤 언어로 가나.

## 결정

**번역 폴백은 영어, 언어 전환은 루트 스택 리셋, 준비 시험 이름은 번역이 아닌 현지화로 한다. 앱 밖 문구는 우리가 문자열을 넘길 수 있는 곳만 앱 설정을 따르고, OS가 그리는 곳은 기기 언어를 따르는 하이브리드로 한다.**

| 표면 | 그리는 주체 | 따르는 언어 | 방식 |
| --- | --- | --- | --- |
| iOS 집중 가림막 · Live Activity · 스크린타임 리포트 · 네이티브 모달 | 우리 코드(익스텐션 포함) | 앱 설정 | App Group(앱과 익스텐션이 함께 쓰는 저장 공간)으로 번역 문자열 전달 |
| 안드로이드 위젯 · iOS 권한 팝업 · 앱 이름 · 스토어 표기 | OS · 런처 · 스토어 | 기기 언어 | `.lproj` · `values-xx` 리소스 |
| 스크린타임 선택 화면 안의 앱·카테고리 이름 | OS | 기기 언어 | 원리상 제어 불가 — 기획 예외로 수용 |

- 문구 톤은 화자 기준이다. 캐릭터(그로몬)는 반말, 앱(시스템)은 해요체다. 번역에서도 유지한다(일본어는 常体와 です・ます).
- 언어를 서버에 보내지 않는 구버전 앱의 푸시 기본값은 ko다. 서버에서 언어가 null이면 그것은 "번역 누락"이 아니라 "업데이트하지 않은 기존 한국 사용자"다.

## 근거

- **`reset()`은 화면만 새로 만들고 컨테이너는 건드리지 않는다.** reset을 하면 라우터가 각 화면에 새 key를 발급해 화면이 다시 마운트되고, 번역 함수 `t()`가 새 언어로 다시 실행된다. `t()`는 React 훅이 아니라 호출 시점의 언어로 한 번 계산하는 함수다. 그래서 언어만 바꾸고 리마운트하지 않으면 이미 그려진 화면은 옛 언어로 남는다. 컨테이너가 그대로이므로 외부 구독자도 살아 있고, `onReady`가 다시 발화하지 않아 첫 화면 조회 이벤트 중복이나 딥링크 재실행 사고도 생기지 않는다.
- **폴백은 "모르는 글자가 튀는 비용"을 최소로 하는 쪽이다.** 한국어는 정본이지만, 번역이 빠진 키에서 한국어를 모르는 사용자에게 한글을 보여 주는 것보다 영어가 낫다. 서버 푸시 번역도 같은 규칙을 따른다.
- **준비 시험은 나라별 제도라 번역하면 존재하지 않는 시험이 된다.** 일본 사용자에게는 「大学入学共通テスト」처럼 그 나라 시험 이름을 보여 준다. 이렇게 하려면 표시명을 로케일별로 받을 수 있어야 하고, 그 전제는 준비 시험을 서버 코드 하나로 옮긴 [ADR-037](/adr/adr-037-occupation-single-source)이 만들었다.
- **저장 버튼 방식은 기존 설정 화면 관례를 따른다.** 준비 시험·목표 설정 화면도 라디오로 고르고 저장해야 적용된다. 저장 전이면 잘못 눌러도 아무 일도 일어나지 않는다.
- **하이브리드는 "우리가 닿을 수 있는 곳"으로 선을 그은 것이다.** 우리 익스텐션이 그리는 표면은 앱 설정을 따르게 할 수 있다(기존 가림막 과목명 전달 선례를 확장). OS·런처·스토어가 그리는 표면에는 앱 설정을 넘길 통로가 없다.

<Callout label="언어 설정 화면은 집중 세션 스택 안에 두지 않는다" tone="warn">
언어 전환은 루트 스택을 새로 만든다. 집중 세션 화면이 그 스택 위에 떠 있으면 세션이 같이 사라진다. 지금 언어 설정은 '전체' 탭에서만 들어오고, 거기에 가려면 세션이 이미 끝나 있어야 한다. 안드로이드 시스템 언어 변경에 자동 리셋을 걸지 않은 것도 같은 이유다.
</Callout>

## 영향

- 번역 검수는 하지 않기로 했다(안수빈 결정, 08-31). 4개 언어 약 6,700 문구가 기계 생성이다. 같은 시기 기록은 사용자가 거의 전원 한국인이라고 적고 있다.
- 시험명 현지화의 부작용으로 같은 준비 시험 리그에 국가가 섞일 수 있다. 최종안은 코드 + 국가로 리그를 나누는 것이지만 글로벌 사용자가 생길 때까지 보류했다(GROMO-1713).
- 네이티브 문구 키는 JS만 바꾸는 OTA(스토어 심사 없이 JS 번들만 내려보내는 업데이트)로 바꾸지 않는다. 새 JS가 그 키를 모르는 옛 바이너리에 떨어지면 신·구 바이너리가 어긋난다 — [ADR-024](/adr/adr-024-ota-hot-updater).
- App Store의 지원 언어 표기는 `.lproj`가 0개라 English 하나로 뜬다. iOS 권한 팝업 번역(GROMO-1712)에 딸려 있다.
- 글로벌 출시 자체는 09-08 멘토링의 "국내 검증하고 글로벌은 나중에"로 보류됐고, 글로벌 후속 9건은 대부분 해야 할 일에 남았다([초심 찾기와 디자인 스프린트](/history/06-reset-and-design)).
- 2.0 앱에는 아직 다국어 레이어가 없다.
