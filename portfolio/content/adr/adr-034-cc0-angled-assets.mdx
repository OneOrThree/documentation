## 맥락

실험 앱 1([ADR-033](/adr/adr-033-redesign-separate-app))의 홈은 아이소메트릭 방이다. 아이소메트릭은 방을 모서리 위에서 비스듬히 내려다보되 원근을 없애, 평행한 선이 화면에서도 평행하게 유지되는 입체 그림이다. 이 방에 놓을 가구와 소품을 돈을 들이지 않고 조달해야 했다.

먼저 이미지 생성 AI로 가구를 직접 그렸다. 한 장에 3×3 시트로 모아 그리면 한 번의 생성이라 색·조명·재질이 완벽히 통일됐다. 그런데 각도가 맞지 않았다. 스프라이트(게임 화면에 올리는 낱장 그림) 윗면의 좌우 기울기를 재 보면 이렇다.

| 스프라이트 | 왼쪽 면 | 오른쪽 면 | 좌우 차 |
| --- | --- | --- | --- |
| 수납함 | 24.5° | 25.5° | 1.0° |
| 침대 | 29.1° | 27.9° | 1.2° |
| 탁자 | 30.4° | 25.4° | 5.0° |
| 책장 | 29.3° | 19.9° | 9.4° |

직교 투영이라면 좌우 기울기가 반드시 같다. 다르다는 것은 원근이 섞였다는 뜻이고, 그러면 어떤 격자에 올려도 맞지 않는다. 눈으로 보면 "대충 맞네" 싶은데 격자에 올리는 순간 전부 틀어진다.

격자 쪽도 문제였다. 게임에서 흔한 2:1 다이메트릭(바닥 기울기 26.57°)으로 바닥을 깔았더니 가구가 전부 어긋났다.

## 선택지

| 선택지 | 문제 | 판정 |
| --- | --- | --- |
| AI로 아이소메트릭 가구 직접 생성 | 좌우 기울기가 최대 9.4° 어긋나 격자에 붙지 않는다 | 기각 |
| Kenney Furniture Kit(CC0, 140종) | 좌우 차 0.13~0.37°, 140종이 같은 카메라. 4방향 렌더와 원본 `.obj` 제공 | 채택 |
| Blender로 직접 배치 렌더 | 정확하지만 설치와 조명·카메라 세팅이 필요하다. 렌더된 PNG가 이미 있어 불필요 | 보류 — 새 가구를 직접 모델링할 때 |
| 다른 CC0 팩(Quaternius·KayKit·Poly Haven) | Kenney로 충분해서 조사를 멈췄다 | 미검토 |
| 벽 걸이도 Kenney에서 | `lampWall`이 위에서 내려다본 각도라 벽등으로 보이지 않고, 종류도 적다 | 기각 — 벽 걸이만 AI |
| 2:1 다이메트릭 격자 | 에셋의 실제 투영과 다르다 | 기각 |

CC0는 저작권을 포기한 라이선스다. 상업적으로 쓰고 고쳐도 되고, 출처 표기 의무도 없다. 계정이나 API 키 없이 zip 하나를 받으면 끝이다.

## 결정

**각도가 있어 격자에 붙어야 하는 방 에셋은 투영이 정확한 CC0 렌더 에셋(Kenney Furniture Kit)으로 조달하고, AI 생성은 벽 걸이처럼 각도가 없는 납작한 면에만 쓴다. 각도는 모델이 아니라 코드가 강제한다.**

| 항목 | 규칙 |
| --- | --- |
| 격자 | `PY = PX / √2`(바닥 기울기 35.264°) 고정 |
| 격자 단위 | 한 칸 = 모델 0.5단위. 바닥 타일 `floorFull` 한 장 = 2×2칸 |
| 발자국(점유 칸) | `.obj`의 XZ 바운딩 박스를 올림. 0.08칸 미만 초과는 무시 |
| 앵커 | `.obj` 밑면 중심을 같은 투영식으로 계산해 점유 칸 중심에 맞춘다 |
| 크기 | 스프라이트 개별 리사이즈 금지. 전체 동일 배율만 |
| 회전 | 시작 오프셋 하나를 고르고 90°씩 강제 |
| 벽 걸이 | AI로 정면 뷰를 생성하고 `skewY(35.264°)`로 벽면에 붙인다 |

```text
// 격자 → 화면
PY = PX / √2
화면x = OX + (col - row) * PX
화면y = OY + (col + row) * PY

// 모델 좌표 → 화면 (고도 45° · 방위 45° 직교 투영)
sx = (X - Z) / √2
sy = (X + Z) / 2 - Y / √2
```

## 근거

- **이미지 모델은 기하를 계산하지 않는다.** "아이소메트릭"이라고 지시하면 아이소메트릭**처럼 보이는** 그림을 그릴 뿐, 투영 행렬(3D 좌표를 화면 좌표로 옮기는 고정된 계산식)을 지키지 않는다. 색·조명 통일은 프롬프트로 되지만 각도는 되지 않는다.
- **격자는 에셋에서 역산했다.** Kenney 스프라이트를 역산하니 고도 45°·방위 45° 직교 투영이었다. 이 투영식으로 예측한 스프라이트 크기가 실제 PNG와 1픽셀 오차로 일치했다. 그래서 발자국과 앵커를 눈대중이 아니라 `.obj` 정점에서 계산할 수 있다.
- **Kenney가 결정적이었던 두 가지.** 렌더 PNG를 4방향(560장)으로 줘서 진짜 90° 회전이 되고, 원본 `.obj` 3D 모델을 같이 줘서 발자국·앵커를 계산으로 뽑을 수 있다. 벽·바닥·문틀 같은 방 구조 타일도 들어 있다.
- **배치 규칙은 실패 3건에서 나왔다.**

| 시도 | 결과 |
| --- | --- |
| 점유 칸을 먼저 정하고 스프라이트를 거기 맞춰 늘림 | 침대가 3배로 부풀었다. Kenney 가구는 이미 서로 비율이 맞춰져 있다 |
| 실루엣으로 발자국 측정 | 책상 상판·침대 이불처럼 밑면보다 튀어나온 부분까지 세어 위치가 밀렸다 |
| "예측 크기 = 실제 크기"로 4방향 회전각 맞춤 | 0°와 180°가 화면에서 같아 구분되지 않았다. 책상을 돌려도 발자국이 안 바뀌고 겹침 판정이 헐거워졌다 |

- **벽 걸이가 AI로 되는 이유.** 시계·액자·거울은 납작해서 각도 오차가 드러나지 않는다. 정면 뷰로 그리고 기울기는 코드가 넣으니, 모델의 기하 오류가 원천 차단된다. 픽셀 아트 작가들이 "정면에서 그린 뒤 기울이기"로 쓰는 기법과 같다. 한계는 상자형에만 된다는 점이다. 책장·서랍장은 정면·측면·윗면을 따로 그려 조립할 수 있지만 의자·소파 같은 곡면은 안 된다.
- **도트(픽셀 아트) 방향도 같은 이유로 닫았다.** 도트로 가면 26.565° 격자가 정본이 되어 Kenney 140종을 통째로 버려야 한다. 게다가 도트는 픽셀 격자가 정확해야 하는데, 디퓨전 이미지 모델은 원리적으로 이를 맞추지 못한다.

## 영향

- **번들 영향은 약 340KB다.** 쓰는 가구 26종의 PNG 104장을 WebP로 바꿔 219KB, 벽 걸이 한 세트 9장이 122KB다. 압축을 푼 킷 전체(20MB)는 앱에 들어가지 않는다. `.obj`도 빌드 전에 발자국·앵커만 JSON으로 뽑고 버린다.
- **같은 날 이 원칙이 뷰 전환의 근거가 됐다.** 정면 단면으로 보는 실험 앱 2('인형의 집')가 나오면서 "한 각도만 있으면 된다"는 조건이 생겼다. 각도라는 개념이 없어지자 아이소메트릭에서 못 쓰던 같은 AI가 가구를 그대로 그렸다(첫 18종, 이튿날 확장분까지 370종).

| | 실험 앱 1 (아이소메트릭) | 실험 앱 2 (정면 단면) |
| --- | --- | --- |
| 스프라이트 | 종당 4장(4방향) | 종당 1장 |
| 에셋 출처 | Kenney CC0 — AI가 실패해서 | AI 생성 |
| 배치 계산 | 투영식·발자국·앵커를 `.obj`에서 산출 | 칸 수와 원본 비율 두 개 |
| 층 쌓기 | 마름모라 좌우에 삼각형 틈 | 사각형이라 틈이 없음 |
| 빌드 스크립트 | 200줄(기하 계산) | 120줄(자르기만) |

- **크로마 키 규칙 두 가지가 남았다.** 크로마 키는 단색 배경으로 그리게 한 뒤 그 색을 투명으로 바꿔 배경을 떼는 방식이다.
  - 디스필(가장자리에 번진 배경색 제거)은 반투명 가장자리에만 건다. 불투명 픽셀까지 누르면 분홍·빨강이 배경색으로 오인돼 회색으로 탈색된다. 실제로 이불과 러그가 죽었다.
  - 08-30부터 배경색을 마젠타 `#FF00FF`에서 녹색 `#00FF00`으로 바꿨다. 마젠타 배경은 생성 단계에서 나무색을 분홍으로 물들였다(실측).
- 아이소메트릭 구현은 실험 앱 2·3으로 옮겨 가며 멈췄다. 2.0의 섬·시설 아트는 별도로 확정돼 이 조달 경로를 잇지 않는다.
