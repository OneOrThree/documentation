## 맥락

08-26, 안수빈은 앱 UI를 전면 개편하기로 했다. 요구는 "조잡해도 되니 완전 귀엽게", 이어서 "완전 다른 앱처럼"이었다.

진단은 그릇과 내용물이 따로 논다는 것이었다. 마스코트(별사탕)는 말랑한 3D 캐릭터인데, 화면은 Linear 계열의 인디고 팔레트(차가운 무채색, 7~12 수준의 작은 모서리, 회색 blur 그림자, 시스템 폰트)였다.

첫 전제는 본 앱의 `theme.ts` 토큰을 갈아끼우는 것이었다. 토큰은 색·폰트·모서리 값을 한 곳에 모아 둔 디자인 변수다. 하드코딩된 색이 없어서 토큰만 바꾸면 전 화면에 퍼진다. 후보로 스타일 4안(말랑 젤리·공책 낙서·도트 다마고치·뽀짝 파스텔)을 만들었다.

걸리는 것이 둘 있었다.

- **1.x는 이미 출시돼 굴러가고 있었다.** 리그·챌린지·스크린타임·재화가 실유저에게 물려 있다. 전면 개편을 본 레포에서 하면 그 전부를 인질로 잡는다. 개편 도중 무언가 깨지면 실유저가 그 비용을 낸다.
- **새로 넣고 싶은 것들은 "되는지부터" 봐야 했다.** 방 꾸미기·그룹 피드·BGM이 그렇다. 디자인 방향도 시안 이미지가 아니라 실물로 만져 봐야 고를 수 있었다.

## 선택지

| 선택지 | 문제 | 판정 |
| --- | --- | --- |
| 본 앱 `theme.ts` 토큰부터 교체 | 실유저 기능을 인질로 잡는다. 검증 전에 얹으면 되돌리기가 비싸다 | 기각 |
| 스타일 4안 중 하나로 리스킨 | 넷 다 상단바 + 카드 + 탭바라는 뼈대를 그대로 두고 색·폰트·모서리만 바꿨다. "완전 다른 앱"이 아니라 같은 앱의 다른 테마다 | 기각(08-27) |
| 실험 앱을 처음부터 운영 서버에 연결 | 붙는 순간 본 앱 API 스펙에 묶여 화면을 바꿀 자유도가 죽는다 | 기각 |
| 별도 실험 앱 + 로컬 목업 + 화면 구조부터 재설계 | 실험 결과를 본 앱으로 옮기는 비용이 나중에 생긴다 | 채택 |

## 결정

**디자인 전면 개편과 새 기능은 운영 중인 앱에서 하지 않는다. 서버에 붙지 않는 별도 실험 앱에서 화면 구조부터 실물로 검증하고, 되겠다 싶은 것만 본 앱으로 가져간다.**

- 본 앱 코드는 참조·복사만 하고 수정하지 않는다.
- 실험 앱의 데이터는 로컬 목업이 먼저다. 운영 서버에 연결하지 않는다.
- 실험 앱은 본 앱과 같은 버전대(Expo SDK 57, React Native 0.86, React 19.2)로 세운다. 가져갈 때 코드가 그대로 옮겨지게 하기 위해서다.
- 개편 단위는 토큰이 아니라 **화면 구조**다. 홈은 방이 화면 전체를 채우고, 지표는 카드가 아니라 방 안의 사물로 표현한다(벽시계 = 오늘 집중, 벽 달력 = 스트릭, 저금통 = 시간조각). 탐색도 사물로 한다(책상 = 집중 시작).
- 문서도 분리한다. 실험 트랙의 기획 노트는 본 앱 기획과 섞지 않고, 본 앱으로 가져가기로 정해지는 시점에 옮긴다.

## 근거

**리스킨이 기각된 이유는 구조가 같기 때문이다.** 4안을 본 안수빈의 반응은 "4개 다 최악. 완전 다른 앱을 만들 거라니까?"였다. 4안은 전부 색·폰트·모서리를 바꾼 것이고, 화면의 뼈대가 같으면 사용자에게는 같은 앱이다. 그래서 바꾸는 단위를 토큰에서 화면 구조로 옮겼다.

**운영 앱과 떼어 놓으니 갈아엎는 비용이 0이 됐다.** 실험 앱 1에서 홈 레이아웃을 08-27 하루에 세 번 갈아엎었다.

| 시도 | 버린 이유 |
| --- | --- |
| 방을 세로로 층층이 쌓기 | 마름모 모양 방을 위로 포개니 좌우에 삼각형 틈이 남아 방과 방 사이가 붕 떴다. 외벽으로 메워도 어정쩡했다 |
| 방 하나 = 한 페이지, 좌우 스와이프 | 틈은 사라졌지만 한 번에 방 하나만 보였다 |
| 떠 있는 섬 여러 채를 한 화면에 흩어 놓은 마을 | 채택. 앞 섬이 뒤 섬을 살짝 가려 깊이가 생긴다 |

구조를 바꿀 때마다 그 구조에만 필요했던 코드는 남기지 않았다. 세로 쌓기의 외벽·지붕·층 겹침 계산과 가로 페이징의 스크롤 로직을 모두 지웠다. 운영 앱이었다면 매번 릴리즈와 되돌리기가 필요했을 변경이다.

- **서버를 붙이지 않았기 때문에 화면 하나를 바꾸는 데 API 계약 협의가 필요 없었다.** 백엔드 일정과 실험 속도가 서로 묶이지 않는다.
- 되돌리기 비용을 먼저 낮추고 수요와 가능성을 확인한다는 점에서, 그룹을 Fakedoor(기능 소개와 "준비중" 안내만 띄워 클릭으로 수요를 재는 가짜 입구)로 먼저 낸 [ADR-018](/adr/adr-018-group-fakedoor-then-backend-first)과 같은 계열의 판단이다.

## 영향

- 나흘(08-27~08-30) 동안 실험 앱 셋이 나왔다.

| 실험 앱 | 형태 |
| --- | --- |
| 실험 앱 1 | 아이소메트릭 방. 홈 = 떠 있는 마을 |
| 실험 앱 2 | 앞 벽을 뗀 건물을 정면에서 보는 '인형의 집' 단면 |
| 실험 앱 3 | 크레용 그림체, 개인 방과 그룹 방 두 개를 좌우로 넘기는 구조 |

- 방 에셋을 어디서 조달하느냐는 뷰의 투영 방식에 따라 갈렸다. 실험 앱 1에서 AI 생성 가구가 격자에 붙지 않은 것이 실험 앱 2로 옮겨 간 이유 중 하나다.
- 09-09 멘토링에서 "UI는 안수빈 것을 가져가고"로 이 트랙이 다음 버전 UI의 축이 됐다([초심 찾기와 디자인 스프린트](/history/06-reset-and-design)).
- 대체된 부분: "되는 것만 1.x로 역이식한다"는 전제는 실행되지 않았다. 2.0은 1.x에 옮겨 붙이는 대신 새 앱으로 따로 세워졌고, 1.x는 09-16에 동결됐다.
