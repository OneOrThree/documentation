## 맥락

준비 시험은 온보딩에서 고르는 "무엇을 준비하는가"다(19종). 같은 시험끼리 리그가 묶이고, 추천 과목과 비교 통계도 이 값에서 나온다.

앱은 이 값을 서버 코드(`CSAT` 같은 식별자)가 아니라 **한글 표시명**("수능/N수")으로 로컬에 저장했다. 서버에는 '알려주기'만 했다. 서버 API는 코드만 받으므로, 앱은 매번 대조표(`CATEGORY_TO_OCCUPATION`)로 표시명에서 코드를 역룩업했다.

이 구조에는 조용히 깨지는 지점이 둘 있었다.

- **대조표는 서버 DB 값을 손으로 베낀 것이다.** 서버 쪽 표기가 바뀌면 대조가 실패한다.
- **알려주기가 실패해도 아무도 모른다.** 실패는 `catch {}`로 삼켜졌고, 화면은 로컬 값을 그리므로 정상으로 보였다. 화면(로컬)과 집계(서버)만 조용히 갈라졌다.

실제로 사고가 났다(ticket 1620). 표시명 3건이 서버 표기와 어긋나, 온보딩을 마친 소수 유저의 `users.occupation`이 NULL로 남았다. 서버 DB 표기를 고쳐 급한 출혈부터 막았다.

## 선택지

| 선택지 | 문제 | 판정 |
| --- | --- | --- |
| 한글 표시명을 매핑 키로 유지 | 서버 표기가 바뀌면 조용히 깨진다 | 기각 |
| 08-25 안 — 로컬 정본을 코드로 전환하고 기존 저장값을 마이그레이션(전용 마커 키, 구 번들 호환용 한글 키 보존) | 소스가 여전히 둘(로컬·서버)이라 또 갈라질 수 있다. 마이그레이션 계약을 새로 져야 한다 | 기각 — 구현 중 번복 |
| 서버 `users.occupation` 하나를 정본으로 | 설정에서 시험을 바꿀 때 네트워크가 필요해진다 | 채택 |
| `occupations` 마스터를 Flyway 마이그레이션으로 승격 | 팀 결정으로 이번 범위에서 뺐다 | 범위 제외 |

Flyway는 DB 스키마와 기준 데이터를 버전 붙은 SQL 파일로 관리하는 도구다.

## 결정

**앱은 준비 시험을 따로 저장하지 않는다. 서버 `users.occupation` 코드 하나가 정본이고, 앱은 시작할 때 이미 부르던 `GET /users/me` 응답을 읽어 쓰며, 표시명은 `GET /occupations`에서 받는다.**

| 구성 | 역할 |
| --- | --- |
| `UserContext.occupation` | 프로필 조회가 씨앗. 화면은 이 값만 읽는다 |
| `occupationSync.ts` | 서버 쓰기의 단일 창구. PATCH 성공이 곧 반영이고, 실패는 `occupation_sync_failed`로 계측한다 |
| `occupationCatalog.ts` | `GET /occupations`로 표시명 조회. 메모리 + AsyncStorage 캐시, 오프라인이면 마지막 성공 응답으로 폴백 |
| `recoverOccupation()` | 서버 값이 NULL이고 폰에 옛 한글 값이 남아 있으면 앱 실행 시 1회 PATCH. 서버에 값이 있으면 아무것도 안 한다 |
| 설정 → 준비 시험 | 하드코딩 배열 대신 `GET /occupations` 목록. 온보딩과 같은 소스, 같은 글자 |

- 소비처 8곳을 코드 축으로 옮겼다(리그 랭킹, 집중 세션, 과목 선택, 메뉴, 비교 통계, 친구 프로필, 앱 부트, 준비 시험 설정).
- 대조표 관련 상수·함수 4종을 지웠다. 앱 전체에서 서버 응답과 한글을 문자열로 대조하는 지점이 0건이 됐다.
- 온보딩이 실패해도 "성공"처럼 보이게 하려고 두었던 로컬 이중화를 없앴다. 옛 로컬 값은 복구 경로가 읽는 읽기 전용 씨앗으로만 남는다.

## 근거

- **코드로 바꾸기만 해서는 '두 소스' 문제가 남는다.** 이번 버그의 원인은 표기 불일치 자체보다 로컬 선반영이었다. 서버 쓰기가 실패해도 화면은 성공으로 보였기 때문에 아무도 알아채지 못했다. 로컬 정본이 남아 있는 한, 키를 코드로 바꿔도 같은 종류의 갈라짐이 다시 생길 수 있다.
- **정본을 없애니 마이그레이션도 사라졌다.** 새 저장 키를 만들지 않으므로 저장 형식 버전도 그대로다. 08-25 안이 요구하던 기존 저장값 마이그레이션과 구 번들 호환 계약이 통째로 필요 없어졌다.
- **복구 변환표는 폰에 실제로 박힌 문자열의 동결 스냅샷이다.** 앱 하드코딩본과 사고 이전 서버 표시명이 섞여 있어 둘 다 담았다.
- **실패를 보이게 만들었다.** 예전에는 `catch {}`가 1620을 가렸다. 이제 쓰기 실패는 계측되고, 설정 화면은 실패하면 안내를 띄우고 그 자리에 남아 재시도하게 한다.
- **계측 파라미터 이름은 `request_source`다.** `source`는 모든 이벤트에 붙는 공통 파라미터와 겹쳐 금지돼 있고, `request_source`는 GA4 맞춤 측정기준에 이미 등록돼 있어 새로 등록할 것이 0건이다.
- **타입 검사가 못 잡는 것은 정합성 테스트로 잠갔다.** 19종 전수 커버와 과목 키 유효성을 검사한다. 어긋나면 칩이 사라지거나 원시 코드가 화면에 뜨는데, 타입으로는 드러나지 않는다. 테스트는 22건이 늘었다.

## 영향

- **트레이드오프:** 설정에서 시험을 바꾸려면 네트워크가 필요하다. 예전에는 오프라인에서도 "일단 저장"됐지만, 바로 그 선반영이 이번 버그의 원인이었다. 온보딩의 시험 선택은 원래도 `GET /occupations` 없이는 진행되지 않아 동작 변화가 없다.
- 피해 유저는 다음 앱 실행 때 스스로 복구된다. 앱을 다시 켜지 않는 계정은 그대로 남는다.
- GA4 차원 값이 한글에서 코드로 바뀌어, 배포 전후로 같은 차원에 두 표기가 섞인다. 탐색 필터를 손봐야 한다.
- **다국어 현지화의 전제가 됐다.** 표시명 조회(`displayNameOf()`)가 i18n 키를 우선하도록 이 변경에서 배선해 두었고, 준비 시험 이름을 나라별 시험으로 보여 주는 [ADR-035](/adr/adr-035-i18n-design)가 그 위에 얹혔다.
- 남은 것: 추천 과목(`GET /tag/defaults`)은 응답에 식별자가 없어 앱만으로는 다국어화할 수 없다. 서버 짝 티켓이 필요하다(GROMO-1705). 리그 라벨 필터의 표시명 기준값도 코드 축으로 옮겨야 한다.
- 기준 데이터가 서버에만 있으면 배포 순서에 묶인다. 07-20 1.0.0 심사 때도 prod에 `occupations` 기준 데이터가 없으면 온보딩이 빈 화면이 되는 선행 조건이 있었다([마이그레이션 사고](/research/migration-incidents)와 같은 계열).
- 2.0에 준비 시험 선택 개념이 남을지는 아직 정해지지 않았다.
