## 맥락

누끼 캐릭터는 사진에서 사물만 오려 낸 이미지(누끼)에 팔다리와 눈을 붙여 만드는 나만의 캐릭터다. 스파이크(GROMO-1022)로 검증한 뒤 08-02에 정식 기능으로 앞당겼다. 서버 개발 부담 때문에 "남에게 보이기"는 뒤로 미루고, **로컬 자기표현 버전**을 먼저 냈다. 이미지는 기기에만 있고 홈·집중 화면·내 아바타·위젯 같은 내 화면에만 쓴다.

원래 계획은 유해 이미지 검사를 서버 공유를 열 때 붙이는 것이었다. 그런데 로컬 저장이어도 유해물로 캐릭터를 만들어 스크린샷으로 SNS에 퍼뜨리면, 앱이 유해물 생성 도구가 된다(안수빈 지적). 스크린샷은 앱이 막을 수 없다.

기기 안에서 검사하는 길도 막혀 있었다. 온디바이스 분류 라이브러리 NSFW.js는 음란물만 분류하고, 기기에서 도는 코드라 우회할 수 있다. 게다가 필요한 `tfjs-react-native`가 Expo SDK 57과 peer 의존성 충돌이 나서 설치할 수 없었다.

08-30에는 다른 벽에 부딪혔다. 이미지가 기기에만 있으니 공유, 신고 검수, 기기를 바꿨을 때의 복원이 전부 불가능했다. 신고센터를 설계하려는데 "운영자가 볼 이미지가 없다"에서 막혔다.

## 결정

**누끼 이미지는 생성 직후, 저장·장착하기 전에 서버 모더레이션을 통과해야 한다. 검사를 하지 못하면 막는다. 서버에 올릴 때는 올라갈 바이트를 다시 검사하고, 재검사에서 떨어지면 업로드만 포기하고 로컬 이미지는 둔다.**

08-02에 구현한 것(PR #422·#424·#426·#430·#431).

| 항목 | 내용 |
| --- | --- |
| 게이트 | 생성 → 서버 모더레이션 API → 통과하면 로컬 저장·장착, 걸리면 거부하고 안내("이 사진으론 만들 수 없어요"). 서버는 검사만 하고 이미지를 저장하지 않는다 |
| 검사 범주 | 성적·폭력·자해. 범주를 넓히는 추가 검사와 기기 쪽 선필터는 후속으로 미뤘다 |
| fail-closed | 검사 자체를 못 한 경우(설정 누락·타임아웃·서버 오류)도 거부로 처리한다. fail-closed는 판단을 못 하면 닫힌 쪽(차단)으로 넘어지는 설계다 |
| 저장물 | 누끼 + 팔다리 + 눈을 합친 합성본 한 장. 생성 화면의 합성 미리보기를 `react-native-view-shot`의 `captureRef`로 캡처해 앱 Documents 폴더에 덮어쓴다. 위젯·Live Activity용 App Group 스냅샷도 같은 한 장이다 |
| 쿼터 | 생성 횟수의 정본은 서버다. 가입 후 7일은 무제한, 그 뒤로는 롤링 7일 2회. 저장까지 완료했을 때만 1회를 센다. 기준일은 설치일이 아니라 계정 가입일이다 |

08-30에 설계한 것.

- 오브젝트 스토리지 업로드 API를 새로 만들고, 업로드할 때 모더레이션을 다시 태운다(GROMO-1693 서버, GROMO-1694 앱 배선).
- 재검사에서 떨어진 건은 재시도 큐에서도 뺀다. 다시 보내도 결과가 같아 비용만 든다.

## 근거

- **게이트 위치**: 스크린샷은 막을 수 없다. 그러니 게이트는 "남에게 보일 때"가 아니라 "만들어질 때"에 있어야 한다.
- **합성본 저장**: 캐릭터 컴포넌트는 팔다리를 표시하는 순간 SVG로 합성한다. 38px 아바타나 위젯에서는 이 합성을 매번 그릴 수 없다(합성 컴포넌트의 최소 박스가 60px). 평면 PNG 한 장이면 어느 크기든 이미지 하나로 축소된다. 고정 파일을 덮어쓰므로 캐시 때문에 옛 이미지가 남는 문제는 주소에 `?t=` 시각 쿼리를 붙여 끊었다.
- **쿼터를 서버에**: 나중에 유료 해제(BM)로 가면 쿼터가 결제 상태와 묶여야 한다. 기기 카운트나 설치일 기준은 재설치로 초기화돼 무제한을 무한히 반복할 수 있다.
- **토큰 재사용 기각**: 토큰은 "어떤 이미지가 통과했다"는 사실만 증명한다. 지금 올라오는 바이트가 그 이미지라는 것은 증명하지 못한다.
- **로컬 이미지 유지**: 로컬 이미지는 생성 게이트를 통과해야만 저장되므로 이미 한 번 검사를 거쳤다. 로컬 전용 캐릭터는 본인만 보므로 피해 범위가 없다. 유해 이미지가 남에게 노출되는 경로는 서버 저장뿐이고, 재검사가 그 경로를 막는다.

받아들인 대가.

- 생성할 때마다 서버 왕복이 생긴다(수백 ms~1초의 "검사 중" 대기). 이 기능은 완전 오프라인이 아니다.
- 재검사까지 붙으면 모더레이션 호출이 캐릭터당 2회(생성 게이트 + 업로드)가 된다. 호출 상한 계산(GROMO-1668)에 2배로 반영해야 한다.
- 아동 성착취물(CSAM)은 이 검사로 잡히지 않는다. 서버 공유를 실제로 열기 전에 전용 탐지 도구를 반드시 확보해야 한다. 선택이 아니라 공유를 여는 전제 조건이다.

## 영향

- 08-02 생성 게이트와 쿼터는 1.1.0(`app-1.1.0-1`)에 들어가 1.x 앱에서 운영 중이다.
- fail-closed 차단이 판정 결과와 구분되지 않아, 검사 서버 장애까지 "이 사진으로는 만들 수 없어요"로 안내되던 결함이 뒤에 드러났다. 응답에 "검사 불가" 구분을 더해 고쳤다(GROMO-1197). 경위는 [누끼 모더레이션 연구 노트](/research/cutout-moderation)에 있다.
- 서버 저장(1693)과 업로드 배선(1694)은 착수되지 않았다. 서버에는 모더레이션·쿼터·생성 기록 엔드포인트만 있고 이미지 업로드 엔드포인트는 없다(09-19 확인). 공유·신고 검수·기기 이전 복원은 여전히 불가능하고, 08-30 결정은 설계로만 남았다. 상태가 "일부 유효"인 이유다.
- 09-09 멘토링에서 방향이 밀렸다. "AI 모더레이션이 실패한다면? 그게 더 어색하다." 실시간 AI 모더레이션은 보류하고, 신고가 들어온 뒤 1차 판정용으로 쓰는 쪽으로 줄었다([멘토링 기록](/history/07-mentoring)). 생성 시점 게이트를 계속 둘지는 재검토 대상이다.
- 2.0에 캐릭터 생성 기능이 있을지 자체가 미결이라, 모더레이션 엔드포인트의 존폐도 판단이 보류돼 있다.
