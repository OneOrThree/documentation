## 맥락

기획 문서가 각자 로컬에 흩어져 있으면 "정본"이라는 말 자체가 성립하지 않는다. 코드 PR과 문서 PR이 따로 움직이면 그 틈에서 다음 구현자가 낡은 문서를 근거로 코드를 고치고, 방금 고친 동작을 되돌린다.

챌린지 문서 세트를 정본으로 이관한 PR은 코드 0줄이었다. 그런데 리뷰를 거치며 결정 로그가 N1~N51까지 쌓이는 사이에 조기 정산 데드패스, 24시간 자동 환불 우회 3종, 삭제 IDOR을 잡았다. 이후 구현 배치에서 정본과 코드가 갈린 8건을 원인별로 판정했고, 그다음 배치에서는 상위 정본의 세 줄이 거짓이라는 걸 찾았다.

## 선택지

| 선택지 | 결과 | 판정 |
| --- | --- | --- |
| 개인 로컬 기획 문서를 그대로 둔다 | 정본이 성립하지 않는다. 코드 주석이 가리키는 문서 주소가 gitignore 대상 스크래치라 팀원이 따라가면 빈손 | 기각 |
| 기능별 문서 세트를 git에 올리되 문서 간 우선순위는 두지 않는다 | 구현자마다 근거로 드는 문서가 달라지고, 같은 기능에 다섯 개의 답이 공존한다 | 기각 |
| 5종 세트 + policy 우선 + 팀 규약은 `conventions/` + `doc/` 브랜치 규칙 | 아래 | 채택 |

## 결정

**기능 하나의 팀 공유 문서는 `docs/prd/<기능>/` 아래 5종 세트로 두고 git으로 추적한다. 문서 간 충돌 시 policy가 이긴다. 기능에 담을 수 없는 팀 전체 규약은 `docs/conventions/`에 둔다.**

| 파일 | 답하는 질문 | 역할 |
| --- | --- | --- |
| `prd.md` | 왜 만드는가? 무엇을 만드는가? | to-be 요구사항(FR), 조건 한눈에, 미해결 항목 |
| `policy.md` | 정책의 근거와 결정 로그 | **정책 정본** — prd와 어긋나면 policy가 맞다 |
| `information-architecture.md` | 사용자가 어디서 어떻게 진입·이동하는가? | 화면·정보 구조, 응답 필드 계약, 로컬 저장소 키 |
| `high-level-design.md` | 어떤 컴포넌트가 어떻게 협력하는가? | 컴포넌트·주요 흐름·시간 모델·동시성·운영 |
| `low-level-design.md` | 정확히 어떤 테이블·API·로직으로 구현하는가? | ERD·엔드포인트 계약·판정 커널·마이그레이션 계획 |

- 결정 로그의 N번호가 정책의 정본이고, 나머지 문서는 그것을 펼친 것이다. N항목은 결정의 역사이므로 현행화하지 않는다. 본문·표·예시만 고친다.
- 개인 스크래치는 gitignore 대상 `doc/`에 둔다(README 기준). `docs/`에는 두지 않는다.
- 팀 규약은 `docs/conventions/`의 `jira-conventions.md`(지라 4축: 도메인·Label·Epic·fixVersion)와 `date-axis.md`(날짜 축 로컬·KST·UTC) 둘이다.
- 문서 브랜치는 신규 `doc/prd-<기능>`, 수정 `doc/fix-prd-<기능>`. 폴더 이름은 kebab-case 영문, 문서는 한국어, 다 갖춰질 필요 없이 있는 것부터 커밋한다.
- 루트·app·back의 `CLAUDE.md`와 티켓 구현·동기화 커맨드가 PRD를 찾는 경로도 `docs/prd/<기능>/` 우선으로 맞춘다. 문서를 옮기는 작업에는 문서를 가리키는 참조를 옮기는 작업이 따라붙는다.

## 근거

- 문서 PR을 코드 PR과 같은 리뷰 게이트에 올리자 결함이 구현 착수 전에 나왔다. 코드 리뷰 8라운드(봇 66건)와 팀 리뷰 4건에서 돈 경로(보고·정산 경합, 탈퇴자 보고 경로 부재, 조기 정산 데드패스, 24시간 자동 환불 우회 3종, 삭제 IDOR), 동시성(생성·종료·삭제 직렬화, 지갑 잠금 순서, write-skew 2종), 계약 정합(알림 중복 제거 아이덴티티, 구앱 호환 브리지, 스키마 마이그레이션 누락)이 잡혔다.
- 정본과 코드가 갈린 8건은 문서 쪽 6건, 구현 쪽 2건이었다. 고칠 것을 정하기 전에 문서 오류·구현 오류·문서 낡음·둘 다 성립 네 축으로 원인을 먼저 갈랐다. 가장 값이 컸던 처분은 개명 철회다. 문서에만 있던 에러코드 이름으로 통일하려다 멈췄는데, 배포된 앱이 `BET_CLOSED`·`BET_NOT_FOUND` 문자열로 분기하고 있었고 enum에는 "이름 변경 금지" 규약이 이미 명문화돼 있었다.
- 상위 정본의 거짓 세 줄은 모두 틀린 방향이 위험한 쪽이었다. LLD 「폐기되는 코드」 4개 중 셋이 지금도 던져지고 있었고, `BET_ALREADY_EXISTS` 하나만 해도 발급 자리가 3곳이었다. 믿었으면 살아 있는 `throw` 경로를 지웠다.
- 계측 이벤트 코드 세 곳의 주석이 가리키던 정본 주소는 상위 디렉터리가 gitignore 대상 개인 스크래치였다. 저장소에 없는 문서는 정본이 아니다.

<Callout label="정본이 코드보다 위험해지는 순간" tone="warn">
"폐기됐다"·"없다"·"항상 그렇다"는 전부 확인 대상이다. 고칠 때는 `grep`으로 발급 경로와 문구 복사본을 세고, 검산 못 한 것은 갭으로 적는다.
</Callout>

## 영향

- 정본 갱신은 계약 변경과 원자적으로 한다. 갈릴 수밖에 없다면 문서 쪽에 "구현 PR과 범위가 겹친다 — 착수 전 대조" 경고를 남긴다. 낡은 문서를 권위로 삼은 정합 작업은 롤백이 된다([타임존 버킷 전쟁](/research/timezone-wars)의 `schema.dbml` 회귀).
- 문서 오류는 개수 대신 방향으로 분류한다.
- 같은 PR의 델타 문서가 고치기 전 문면을 인용하는 자기모순이 실제로 났다. CI 러너가 5/5 offline이던 시기라 독립 검증은 사람과 사전 게이트 2라운드뿐이었다.
- 챌린지·내기 이벤트 11종의 계측 정본을 코드 0줄로 신설했고, 측정할 수 없는 7건은 갭 표로 남겼다. "미노출률" 같은 비율 지표는 분모가 빠져 과대 추정이 되므로 절대 건수로 계약을 바꿨다.
- 출처 시점 차이: 정본화 기록에는 팀 규약(날짜 축)을 `docs/` 최상위(`docs/date-axis.md`)에 둔다고 적혀 있고, 현재 README는 `docs/conventions/date-axis.md`를 가리킨다. 이 ADR은 README를 현재 상태로 본다.
