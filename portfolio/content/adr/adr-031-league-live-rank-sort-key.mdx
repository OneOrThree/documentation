## 맥락

리그 순위의 원천은 `daily_focus_stats`(유저별 하루 집중 합계 테이블)의 주간 합계다. 이 테이블은 세션이 끝나는 시점(`FocusService.recordCompletion`)에만 갱신된다.

앱은 다르게 그린다. 집중 중인 유저의 시간은 `totalFocusSeconds + (now − focusStartedAt)`로 매초 자란다(`LiveFocusTime`). 같은 화면에서 한쪽은 매초 움직이고 한쪽은 멈춰 있으니 둘이 어긋났다.

- **집중 중에는 순위가 멈춰 보인다.** 한 시간째 집중하고 있어도 세션이 끝나기 전까지 순위는 그대로다.
- **시간과 순위가 뒤집힌다.** 표시 시간은 위 행보다 많은데 순위는 아래에 있는 "시간은 위인데 순위는 아래" 목록이 된다.
- **무한 모드(카운트업)는 세션이 끝날 때까지 순위가 통째로 고정된다.** 끝나는 시점이 정해지지 않은 모드라 가장 오래 멈춰 있다.

## 선택지

| 선택지 | 문제 | 판정 |
| --- | --- | --- |
| 현행 — 확정 집계만으로 정렬 | 집중 중 순위 정지, 시간·순위 역전 | 기각 |
| 응답 `totalFocusSeconds`에 경과를 실음 | 앱이 같은 구간을 한 번 더 더해 **이중 계상**된다 | 기각 |
| 주간 정산에도 라이브 값 사용 | 주간 마감은 확정값이어야 한다([ADR-010](/adr/adr-010-idempotent-settlement)) | 기각 |
| keyset 페이지 커서도 라이브 값으로 정렬 | 계속 변하는 값으로 정렬하면 페이지가 **건너뛰거나 중복**된다 | 기각 |
| 순위 조회의 정렬 키에만 경과 가산 | 응답·정산·커서는 그대로 두고 순서만 화면과 맞춘다 | 채택 |

keyset 페이지네이션은 "마지막으로 본 행의 정렬 값"을 커서로 넘겨 그다음 행부터 가져오는 방식이다. 커서가 가리키는 값이 요청 사이에 움직이면 경계에 있던 행이 두 페이지에 모두 나오거나 어느 페이지에도 안 나온다.

## 결정

**리그 순위 조회(`findTop`·`findRankOf`)의 정렬 키에만 진행 중 세션 경과를 더한다. 응답 값, 주간 정산, keyset 페이지 커서는 확정 집계를 그대로 쓴다.**

| 항목 | 규칙 |
| --- | --- |
| 라이브 세션 | 유저당 최신 미종료 세션 1건(`DISTINCT ON (user_id)`) |
| orphan 제외 | `started_at`이 now − 12시간 이후인 것만. 앱의 '집중 중' 표시 기준(`LIVE_SESSION_MAX_AGE`)과 같은 값이라 순위와 표시가 같은 세션 집합을 본다 |
| 주 경계 | 주 시작 전에 시작한 세션은 주 시작으로 클램프해 이번 주 몫만 센다 |
| 기준 시각 | 한 요청 안에서 `now` 하나를 인자로 받아 공유한다 |
| 응답 | `totalFocusSeconds`는 확정값. 라이브 필드(`focusStartedAt` 등)는 따로 싣는다 |
| 전역 랭킹 | 정렬만 라이브로 바꾸면 "위 행이 아래 행보다 시간이 적은" 목록이 되므로 라이브 필드도 채운다 |
| 앱 파생 계산 | 격차·평균을 라이브 점수 축으로 맞춘다(#682) |
| 건드리지 않음 | 정산 쿼리 3종, 알림용 `findGlobalRankingPage`(keyset 커서) |

orphan은 앱이 강제 종료되는 등 비정상으로 끝나 종료 시각이 남지 않은 세션이다.

## 근거

- **서버 정렬 점수와 앱 표시가 같은 식이 된다.** 서버가 응답에 싣는 `focusStartedAt`은 정렬에 실제로 쓴 앵커(주 경계 클램프 후)다. 그래서 앱의 `base + (now − focusStartedAt)`가 서버 정렬 점수와 정확히 같고, 순서와 표시가 일치한다.
- **응답 값을 확정값으로 둔 이유는 이중 계상이다.** 앱은 이미 경과를 더해 그린다. 서버가 경과를 포함한 값을 주면 같은 구간이 두 번 더해진다.
- **스키마 변경이 없다.** 미종료 마커를 찾는 기존 부분 인덱스(`idx_focus_sessions_live_marker`, `WHERE ended_at IS NULL`)를 그대로 탄다. 응답 계약이 그대로라 앱을 바꾸지 않아도 순위가 움직이고, 구 번들도 그대로 동작한다.
- **Postgres `GREATEST`·`LEAST`는 NULL 인자를 건너뛴다.** 대부분의 SQL 함수는 NULL이 하나라도 섞이면 NULL을 돌려주지만 이 둘은 다르다. 진행 중 세션이 없는 유저는 `live.started_at`이 NULL인데, `GREATEST(NULL, :weekStartAt)`은 NULL이 아니라 `:weekStartAt`을 돌려준다. 그러면 집중하지도 않은 유저 전원에게 "주 시작부터 지금까지"가 붙고, 실제로 집중 중인 유저가 오히려 밀린다. 개발 중 실제로 밟았고 `CASE`로 분기했다.

```sql
-- 틀린 것: 진행 중 세션이 없어 live.started_at 이 NULL 이면 :weekStartAt 이 나온다
GREATEST(live.started_at, :weekStartAt)

-- 고친 것: NULL 을 먼저 분기한다
CASE WHEN live.started_at IS NULL THEN 0
     ELSE GREATEST(0, EXTRACT(EPOCH FROM :now - GREATEST(live.started_at, :weekStartAt)))
END
```

- **앱 쪽 파생 계산도 같은 축이어야 했다(#682).** 서버 정렬이 바뀐 뒤 앱은 여전히 확정값끼리 빼서 격차를 냈다. 확정 600초 + 경과 1시간으로 내 위에 올라온 행과의 격차가 음수가 되어 `00:00:00`으로 표시됐다. 상위 100명 표본이 라이브 점수로 뽑히는데 평균을 확정값으로 내면 평균도 체계적으로 낮아진다. `memberLiveSeconds`(확정 주간 초 + 집중 중이면 경과)를 두고 격차·평균을 모두 이 값으로 계산했다.
- 테스트: 리포지토리 테스트 4건을 더했다. 경과가 정렬에 반영되고 응답값은 확정값 유지(확정 600초 + 라이브 3,600초가 확정 3,000초를 앞선다), 세션이 끝나면 확정 기준으로 정정, 12시간 넘은 orphan 제외, 주 경계 세션은 주 시작 이후 몫만. 앱은 `memberLiveSeconds` 유닛 3건(구 서버 응답 폴백 포함)을 더했다.

## 영향

- **세션이 끝나면 순위가 조금 내려갈 수 있다.** 일시정지한 시간은 종료 시점에 차감된다. 진행 중에는 순수 경과를, 종료 뒤에는 차감된 값을 센다. 화면의 시간도 같은 시점에 같이 줄어서 표시와 순위는 계속 일치한다.
- **orphan 세션은 최대 12시간 동안 순위를 부풀린다.** 원래 '집중 중' 표시가 갖고 있던 갭이고, 이 변경으로 순위와 표시가 최소한 같은 세션 집합을 보게 됐다. 창을 줄이려면 표시 기준도 함께 줄여야 해서 세션 생존 판정 쪽([ADR-007](/adr/adr-007-focus-session-liveness))과 묶어 별건으로 남겼다.
- **리그 화면은 폴링이 없다.** 화면에 들어올 때만 조회하므로 리그 탭을 켜 둔 채로는 여전히 순위가 고정으로 보인다(재진입·당겨서 새로고침 때 갱신). 폴링을 붙이는 것은 요청량·배터리와의 트레이드오프라 후속으로 뺐다. 순위 상승 연출(한 칸씩 올라가는 재생)이 라이브 점수를 모르는 문제도 후속이다.
- 리그 도메인은 2.0에 대체 계약이 없어 1.x 지원 종료 뒤 삭제될 예정이다. 이 결정도 1.x와 함께 끝난다.
