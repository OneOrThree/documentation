## 맥락

초기 인게임 재화는 `POST /currency/earn`이었다. 클라가 금액과 사유를 body에 담아 보내고 서버는 잔액을 그만큼 올렸다. 내기 시스템이 붙어 코인이 판돈이 되자 이 엔드포인트는 클라가 부르는 금액을 그대로 찍어 주는 발행기가 됐다.

6월 초부터 8월 10일까지 재화·정산 워크스트림 18개 PR에서 잡은 돈 결함은 세 자리로 수렴했다.

- 철회 후 재참여하면 참가비가 0원이었다. 멱등키가 `bet:{betId}:stake:{userId}`(유저 축)라 참가 행을 지우고 다시 만들면 같은 키에 걸려 조용히 skip됐고, 호출부는 `false` 반환값을 버렸다.
- 내기 취소와 그룹 탈퇴가 겹치면 같은 참가비가 두 번 환불됐다. 탈퇴 경로가 잠금 전 평문 SELECT로 대상을 뽑고, 두 경로가 공유 락으로 유저를 읽고, 환불 키 축이 경로별로 갈려 있었다.
- 리그 주간 정산이 전 유저 단일 트랜잭션이라 정산 중 탈퇴 1건이 전체를 롤백했고, 버전 없는 full-row UPDATE로 탈퇴가 파기한 PII가 부활했다.
- 정산 진입점이 크론·조기 확정·수동 배치로 여럿이라, 수동 배치 전체 호출이 SCREEN_TIME 회차를 하루가 끝나기 전에 정산할 수 있었다.

## 선택지

| 자리 | 기각한 대안 | 채택 |
| --- | --- | --- |
| 금액의 출처 | `earn` 제거(구앱이 500) / `earn` 유지(구앱이 두 번 지급) | 세션 저장 트랜잭션 안에서 서버가 계산·기입. `earn`은 잔액·원장 무변화 no-op으로 204 유지 |
| 멱등키의 축 | 유저 축 `bet:{betId}:stake:{userId}` | 참가 행 축 → 회차 축 `session:{sid}:refund:{participantId}` 단일 키 |
| 유저 행 락 | 공유 락으로 읽고 뒤늦게 쓰기 | 처음부터 배타 락. 잠금 순서 유저→멤버십→회차→지갑 고정 |
| 리그 정산 | Spring Batch Step 이관(GROMO-892) | 오케스트레이터 무트랜잭션 + 유저 1명 = 트랜잭션 1개 + 멱등 재실행 |
| 정산 진입점 | 트리거별 개별 진입 | `settle(sessionId, trigger)` 단일 진입점, trigger ∈ CRON \| EARLY \| MANUAL |

## 결정

**재화 금액은 서버만 정하고, 돈이 움직이는 모든 경로는 사건 단위 멱등키·배타 락·단일 정산 진입점을 지킨다.**

```java
// 세션 저장 트랜잭션 안에서 지급 — 멱등키가 같은 세션의 이중 지급을 차단
credit(user, SESSION_COMPLETE, reward, "focus:" + sessionId + ":reward");
```

- 보상 공식은 앱이 쓰던 `floor(집중초 / 10)`을 포팅했다. 집중초는 `(endedAt − startedAt) − totalDistractionSeconds`이고 경계값 12종을 단위 테스트로 고정했다.
- 차감의 `false` 반환은 트랜잭션 전체를 되돌린다. 차감 없는 참가 행이 남는 것보다 요청 실패가 안전하다.
- 취소·철회·탈퇴·무산의 환불 키를 하나로 통일해 차감 키와 1:1로 대응시킨다. "한 번 걷힌 참가 행은 어떤 경로로든 정확히 한 번만 돌아온다"를 원장 유니크가 보장한다.
- `settle`은 회차를 `FOR UPDATE`로 선점하고 OPEN이 아니면 즉시 반환한다. 24h 환불이 모든 트리거에서 최우선이다.
- 정산이 영구히 불가능해진 회차는 24시간이 지나면 환불 상태로 닫고 전원 환불한다. 이미 정산된 건은 그대로 둔다.

재화 PRD §6이 같은 원칙을 정책으로 확정했다. P1 클라 적립 전면 폐쇄(`earn` no-op), P2 `isServerOnly()` 가드로 서버 전용 6종 타입을 클라 경로에서 거절, P4 낙관 가산 금지, P6 선지급 금지, P7 금액을 지어내는 폴백 금지. §3.2는 획득 이벤트(`currency_earned`)를 서버 소유로 둔다. 내기 정산과 리그 승급은 앱이 꺼져 있는 배치에서 지급되므로 클라가 소유하면 그 경로가 측정에서 통째로 빠진다.

## 근거

- 차감은 유저가 자기에게 불리한 방향으로만 조작할 수 있어 `/currency/spend`는 사유 화이트리스트와 양수 검증으로 충분했다. 지급은 결이 다르다.
- 참가 행은 참가마다 새로 만들어지는 UUID v7이라 키에 넣으면 회차가 키 수준에서 갈린다. 축을 바꾸면서 철회 환불이 정산 환불 키를 미리 소진하던 유저 손해 쪽 버그도 함께 닫혔다.
- 이중 환불은 `CyclicBarrier` 강제 인터리빙 테스트로 옛 동작을 복원해 3회 중 3회 실패(`expected: 1L but was: 2L`)를 확인한 뒤 고쳤다. 이 순서가 없으면 그린이 "고쳤기 때문"인지 "그 경로를 안 타기 때문"인지 구별할 수 없다.
- 건 안에서 유저를 배타 락으로 재조회하면 탈퇴가 선커밋된 경우 예외 없이 스킵되고, 락을 먼저 쥐면 탈퇴가 직렬화돼 지갑 생존이 보장된다. PII lost update 창도 같이 닫힌다.
- B3 재편 후 철회×탈퇴·참가×탈퇴 인터리빙 테스트가 환불 1회·유령 유료 참가 0으로 통과했다(tests 1497 · failures 0).

## 영향

- 회차 id로 구 내기 행 id를 재사용해 원장 멱등키와 알림 dedup이 참조하는 id를 불변으로 유지했다. 스키마를 바꿔도 멱등성 불변식이 마이그레이션을 통과한다.
- 스크린타임 권한을 철회한 유저는 미계측 = 미달성으로 확정한다. 반대로 판정하면 측정을 끄는 행위가 승리 조건이 된다.
- 잔액은 여전히 mutable 컬럼이고 거래 기록 테이블은 원장의 씨앗이다. 지향점은 이중부기 원장(잔액은 프로젝션, 정정은 역분개만)이며, 단계 3 중 멱등키만 확보됐다.
- 남은 것: 구매 멱등키 없음(GROMO-712), 잔액 차감 낙관적 락에 재시도 없음, 역분개 미설계, 일 1회 3중 대사 미착수.

<Callout label="전제" tone="warn">
정산은 불가역이다. 잘못 나간 지급을 원장에서 되돌릴 역분개가 아직 없으므로, 판정이 확정되기 전에는 지급하지 않는다(PRD P6).
</Callout>
