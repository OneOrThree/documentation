## 맥락

GA4(Google Analytics 4)는 앱에서 일어난 사건(이벤트)을 모아 지표를 계산하는 분석 도구다. 이벤트는 앱이 직접 보낼 수도 있고, 서버가 Measurement Protocol(MP)이라는 서버용 통로로 보낼 수도 있다. gromo의 이벤트 분류표는 이벤트마다 누가 보낼지(소유권)를 정해 두었고, 집중 세션 완료 `focus_session_completed`는 서버 소유였다. 앱 코드에는 "서버 소유라 클라 발행 금지"라는 주석까지 있었다.

07-30 prod GA4를 전수 확인하니 서버(MP) 이벤트가 0종이었다. 서버 쪽 발행이 배선되지 않았던 것이다. 그래서 `focus_session_completed`가 한 건도 없었고, 이 이벤트로 계산하는 지표 셋이 전부 측정 불가였다. 핵심 주간 활성 사용자(core WAU), 활성화 마커(가입 후 첫 완료), 퍼널의 완료 칸이다.

구현하면서 "완료"의 정의가 갈렸다. 카운트업(끝 시각 없이 올라가는 타이머)은 사용자가 정지 버튼을 눌러야 끝난다. 그런데 기존 코드는 정지 버튼 종료를 포기(`focus_session_abandoned`, 사유 `user_exit`)로 보냈다. 여기에 완료 이벤트를 붙이면 한 세션이 완료와 포기 양쪽에 잡힌다.

## 선택지

| 선택지 | 판정 | 이유 |
| --- | --- | --- |
| 서버 소유 유지, MP 배선을 기다림 | 기각 | 배선할 때까지 핵심 지표가 빈다. prod에서 실제로 0건이었다 |
| 앱이 세션 종료 지점에서 발행 | 채택 | 세션이 끝나는 순간 앱이 떠 있어 확실히 보낼 수 있다 |
| 카운트업 정지를 완료 + 포기로 이중 발행 | 기각 | 한 세션이 두 칸에 잡혀 퍼널이 깨진다 |
| 짧은 세션은 앱이 걸러 발행하지 않음 | 기각 | 필터 기준이 바뀌면 과거 데이터를 되살릴 수 없다. 거르기는 분석 단계에서 한다 |

## 결정

**`focus_session_completed`는 앱이 세션 종료 지점 `finish()`에서 발행한다. 사용자가 직접 끝낸 세션(완주 확인·정지 버튼)은 카운트업·카운트다운·뽀모도로 모두 완료로 세고, 한 세션은 완료와 포기 중 정확히 하나만 발행한다.**

| 항목 | 내용 |
| --- | --- |
| 발행 지점 | 모든 종료가 모이는 `FocusSessionScreen`의 `finish()`. 기존 1회 가드(`finishedRef`)를 재사용 |
| 파라미터 | `mode` · `focus_minutes`(실제 집중 초를 분으로 반올림) · `has_tag`(과목 태그 유무) |
| 0분 세션 | 발행한다. 거르는 것은 분석 단계에서 `focus_minutes`로 |
| 포기 이벤트 | 정지 버튼의 `user_exit` 발행을 없앴다. `focus_session_abandoned`는 이탈 타임아웃(`leave_timeout`)처럼 `finish()`를 거치지 않은 종료에만 남는다. 둘의 상호배타는 `abandonedRef`가 보장한다 |
| 별점 게이트 | 별개 기준으로 유지한다. 중도 정지한 세션에는 별점 창을 띄우지 않는다(GROMO-980) |

## 근거

- 세션 종료는 사용자가 앱 화면에서 버튼을 누르는 사건이다. 그 순간을 가장 확실히 보는 것은 앱이다. 서버는 종료 요청을 받긴 하지만, 그 요청을 GA4로 보내는 배선이 없으면 아무 소용이 없었다.
- 한 세션 = 이벤트 하나로 만들면 퍼널의 칸이 서로 겹치지 않는다. 완료와 포기를 나란히 세도 한 세션이 두 번 세어지지 않는다.
- 0분 세션을 버리지 않는 것은 되돌릴 수 있는 쪽을 고른 것이다. 보내 둔 이벤트는 분석에서 걸러낼 수 있지만, 보내지 않은 이벤트는 되살릴 수 없다.
- "정지 버튼 = 완료"는 계측 기준이다. 별점 게이트는 "끝까지 했는가"라는 다른 질문에 답하므로 기준을 합치지 않았다.

<Callout label="해석 — 원문에 적힌 원칙이 아니다" tone="primary">
[ADR-009](/adr/adr-009-server-owns-money)는 재화 획득 이벤트(`currency_earned`)를 서버 소유로 둔다. 내기 정산과 리그 승급은 앱이 꺼져 있는 배치에서 지급되기 때문이다. 이 ADR은 반대로 완료 이벤트를 앱으로 옮겼다. 두 결정을 나란히 놓으면 "사건이 일어나는 순간 확실히 살아 있는 프로세스가 그 이벤트를 소유한다"는 기준이 보인다. 이 기준은 08-01 결정기록이나 이벤트 분류표에 적힌 원칙이 아니라, 두 결정을 대조해 이 문서에서 읽어 낸 해석이다.
</Callout>

## 영향

- 서버 MP를 배선할 때(짝 백엔드 티켓) `focus_session_completed`는 반드시 빼야 한다. 둘 다 보내면 이중 집계가 된다.
- 이 배포 시점부터 `focus_session_abandoned`의 `user_exit` 계열이 끊긴다. 그 수치를 보던 대시보드는 배포일 앞뒤를 다르게 읽어야 한다.
- GA4 콘솔에 `mode`·`has_tag` 측정기준과 `focus_minutes` 지표를 손으로 등록해야 했다. 코드 배포만으로는 끝나지 않는 작업이다.
- JS만 바뀐 변경이라 OTA로 내보낼 수 있었다.
