## 측정 조건

```bash
k6 run --vus 200 --duration 5m scripts/hotzone.js
```

| 항목 | 값 |
| --- | --- |
| 동시 사용자 | 200 |
| 지속 시간 | 5분 |
| 대상 | `GET /api/zones?bbox=...` |
| 캐시 상태 | 워밍업 후 |

## 결과

| 지표 | 목표 | 실측 |
| --- | --- | --- |
| p95 | < 300ms | 118ms |
| p99 | < 800ms | 402ms |
| 5xx 비율 | < 1% | 0.02% |

목표는 모두 통과했다. 다만 워밍업 없이 시작한 첫 회차에서 p99가 3,100ms까지 튀었다.

## 병목은 Redis가 아니었다

캐시 미스가 몰린 구간에서 재계산 쿼리가 동시에 여러 번 실행되고 있었다. 같은 키에 대한 재계산이 중복으로 도는 전형적인 캐시 스탬피드다.

<Callout label="배운 것">
캐시 히트율만 보면 건강해 보인다. 문제는 미스가 **동시에** 나는 순간이고, 그건 평균 지표에 거의 드러나지 않는다.
</Callout>

## 후속

- 재계산 경로에 키 단위 분산 락을 건다.
- 배포 직후처럼 캐시가 비는 순간을 별도 시나리오로 측정한다.
