## 구성 요소

| 이름 | 역할 | 스택 |
| --- | --- | --- |
| 모바일 앱 | 촬영·업로드·조회 | TypeScript |
| API 서버 | 인증, 조회, 업로드 승인 | Spring Boot |
| 인코딩 워커 | 업로드된 원본 트랜스코딩 | Java |
| PostgreSQL | 원본 데이터 | PostgreSQL 16 |
| Redis | 집계·캐시 | Redis 7 |
| S3 | 원본·결과물 보관 | AWS S3 |

## 업로드 경로

앱은 파일을 API로 보내지 않는다. API에서 presigned URL을 받아 S3에 직접 올리고, 완료를 커밋한다.

```java
// 업로드 승인만 API가 담당하고, 바이트는 S3로 직행한다
public PresignedUpload authorize(UploadRequest req, UserId user) {
    quota.assertWithin(user, req.sizeBytes());
    var key = ObjectKey.forUpload(user, req.contentType());
    return s3.presignPut(key, Duration.ofMinutes(10));
}
```

커밋을 받은 API가 큐에 작업을 넣고, 워커가 집어 간다. **API는 인코딩 완료를 기다리지 않는다.**

## 조회 경로

- 단건·목록 조회는 PostgreSQL을 직접 읽는다.
- 집계 조회는 Redis Sorted Set을 읽고, 미스일 때만 Postgres에서 재계산한다. 근거는 [ADR-002](/adr/adr-002-postgres)에 있다.

## 경계에서의 약속

1. 워커는 API의 DB 스키마를 직접 읽지 않는다. 필요한 값은 작업 메시지에 담는다.
2. 앱은 S3 키를 직접 만들지 않는다. 언제나 API가 발급한다.
3. Redis에 있는 값은 언제든 사라질 수 있다고 가정한다.
