## 축이 둘이다 — Gromo 1.x 와 같이숲 R61

<Callout label="아래 본문은 1.x 축의 기록이다" tone="warn">
2026-09-10에 제품이 **「같이숲」**으로 재설계됐다. 이름만 바뀐 것이 아니라 재화·성장 구조·핵심 루프가 전부 다시 정의됐다. 이 문서의 아래 본문은 **그 이전 제품(Gromo 1.x)**의 정의이고, 지우지 않고 남겨 둔다 — 출시된 앱이 그것이고, 아래에 적힌 실드·스크린타임·그룹방은 실제로 만들어 App Store에 올린 것이기 때문이다. 지금 만들고 있는 제품을 알려면 이 절과 [R61 유스케이스](/spec/use-cases)를 본다.
</Callout>

두 축의 차이를 한 표로 둔다. 왼쪽은 아래 본문, 오른쪽은 [2026-09-14 정책 정본](https://github.com/OneOrThree/planning-document/blob/main/policy-2026-09-14.md)이다.

| --- | --- | --- |
| 한 줄 정의 | 집중시간은 늘리고 무의미한 폰 사용은 줄이는 소셜 집중 관리 앱 | 같은 섬에 속한 주민들이 각자 집중해 모은 물고기로 마을을 함께 키우는 앱 |
| 소속 단위 | 그룹방 | **섬** — 복수 소속 가능, 메인 섬 하나 |
| 집중 방식 | 무제한·카운트다운·뽀모도로 + 실드 | **카운트업만.** 목표 시간 입력 없음. 뗏목으로 낚시섬에 이동해 원하는 자리에서 집중 |

| 소통 | 실시간 그룹 채팅(뺀 것) | **우체통** — 우리 섬 편지방 + 친구 비동기 편지(열람 후 삭제). 실시간 1:1 없음 |
| 기록 공개 | 공개 범위 설정 | **도서관 완공 후 전체 공개 고정.** 사용자 설정 없음 |

## 이 문서의 위치

이 문서는 2026-08-11 사용자 인터뷰형 기획 검증에서 합의된 내용을 누적한 **기획서 재작성 초안**을 기준으로 쓴다. 그 초안은 앱 저장소의 기존 기획서 정본을 최종 합의 전까지 덮어쓰지 않는 작업 문서이고, 실제 구현과 확인된 제품 의도를 구분하는 것을 원칙으로 둔다. 이 페이지도 같은 구분을 유지한다.

<Callout label="읽는 법" tone="primary">
본문에서 **확인된 구현**은 초안이 "현재 구현" 또는 "현재 정책"으로 적은 것, **제품 의도**는 초안이 목표·가치로 적은 것, **후속 가설**은 초안이 "후속 제품 가설"·"미확정"으로 표시한 것이다. 세 가지를 마지막 표에서 한 번 더 모아 둔다.
</Callout>

## 한 줄 정의

> 집중시간은 늘리고, 무의미한 스마트폰 사용은 줄이는 소셜 집중 관리 앱

사용자에게 전달할 때는 "집중할 때는 스마트폰 딴짓을 방어하고, 집중한 뒤에는 같은 목표를 가진 사람과 과목별 공부시간을 비교하는 앱"으로 쓴다. 딴짓 방어는 집중 순간의 즉시적 효용이고, 과목별 공부시간 비교가 다른 집중·차단 앱과 Gromo를 구분하는 핵심 소셜 가치다.

초안은 `핵심`이라는 말이 여러 기능에 무분별하게 붙지 않도록 제품 가치를 다음처럼 나눈다.

| 구분 | 가치 |
| --- | --- |
| 핵심 사용 이유 | 집중할 과목을 선택하고 시간을 기록한다 |
| 즉시적 효용 | 세션 중 허용하지 않은 앱으로의 이탈을 실드로 막는다 |
| 구조적 차별점 | 집중기록과 선택 앱 스크린타임을 한 앱에서 함께 관리한다 |
| 핵심 소셜 차별점 | 같은 시험·목표의 사람과 과목별 공부시간과 선택 앱 사용시간을 비교한다 |
| 소셜 리텐션 | 현실 친구와의 동행감·챌린지·내기·콕이 다음 집중을 만든다 |

제품의 핵심 결과는 ① 사용자가 정한 집중시간 목표 달성과 ② 사용자가 선택한 관리 대상 앱의 사용시간 목표 달성을 동시에 이루는 것이다. 대표 성과지표 **후보**는 두 목표를 동시에 달성한 날의 비율이다.

## 타깃 사용자

### 행동 기반 핵심 타깃

> 공부·독서·자기계발처럼 일정 시간 이상 집중해야 하는 활동을 반복하지만, 알림이나 습관적인 스마트폰 확인 때문에 집중 시작이 늦어지거나 이미 시작한 집중이 자주 끊기는 사람

타깃은 특정 시험 준비생으로 제한되지 않는다. 시험 준비생·독서하는 사람·자기계발 학습자는 활동이 다르지만 같은 행동 문제를 공유한다 — 집중 중 알림이 오면 무심코 확인한다, 알림 하나만 보려다 SNS·숏폼·영상 앱으로 이동한다, 친구가 무엇을 하는지 궁금해 불필요하게 연락하거나 SNS를 확인한다, 집중 전에 콘텐츠를 잠깐 보려다 시작 시점을 놓친다, 시간이 지난 뒤에야 무의미한 사용을 인지하고 자책한다.

### 초기 검증 사용자와 확장 사용자

| 범위 | 대상 | 근거 |
| --- | --- | --- |
| 초기 검증 | 시험 준비생·자기계발 학습자. 특히 장기 시험 준비생 | 거의 매일 반복 집중, 시간 단위 목표 설정, 여러 과목의 시간 배분, 같은 시험 준비생과 비교하려는 동기, 스마트폰 이탈의 큰 기회비용, 일·주 단위 행동 변화 측정 가능 |
| 확장 | 독서 습관을 만들고 싶은 사람, 어학·코딩·직무 공부를 하는 자기계발 사용자, 업무·사이드 프로젝트에 집중하려는 사람, 특정 SNS·영상·게임 사용시간을 줄이고 싶은 사람 | 별도 가설로 다룬다 |

넓은 행동 기반 타깃과 과목별 비교라는 차별점은 모순이 아니지만, 모든 타깃이 모든 기능에서 같은 강도의 가치를 얻는다고 주장하지 않는다.

| 사용자 범위 | 우선 가치 |
| --- | --- |
| 모든 집중 행동 사용자 | 활동별 집중 기록, 실드, 선택 앱 스크린타임 관리 |
| 시험 준비생·다과목 학습자 | 위 가치 + 같은 시험 사용자와의 과목별 시간 비교 |
| 현실 친구·스터디와 함께 쓰는 사용자 | 위 가치 + 동행감·챌린지·내기·콕 |

## 핵심 문제 — 가장 먼저 해결할 장면

가장 우선해서 해결하는 문제는 **집중 중 알림이나 충동으로 스마트폰을 열어 다른 앱에 장시간 이탈하는 순간**이다. 집중 시작 전 "이것만 보고 해야지"라며 시작을 미루는 문제도 같은 타깃의 중요한 상황이지만, 세션 실드가 직접 개입하는 1차 장면은 집중을 시작한 뒤의 앱 이탈이다. 시작 전·세션 밖의 무의미한 사용은 선택 앱 스크린타임 기록·목표·소셜 비교로 관리한다.

대표 장면은 "공부 중 Instagram 알림으로 화면이 켜짐 → 알림 확인을 위해 진입 → 최초 목적을 잊고 피드를 1시간 소비 → 뒤늦게 시간 손실 인지 → 자책과 의욕 저하 상태로 재개"다. 손실은 계획하지 않은 사용시간, 집중 맥락의 손실, 재집중까지의 회복시간, 자책과 의욕 저하로 나뉜다. Gromo가 직접 끊으려는 연결은 `짧은 알림 확인 → 차단 없는 앱 진입 → 장시간의 비의도적 콘텐츠 소비`다.

## 매일 재방문을 만드는 핵심 습관

가장 기본적인 재방문 동력은 소셜 경쟁이 아니라 **사용자가 집중하려는 순간 가장 먼저 떠올리는 도구가 되는 것**이다. 기능의 역할 우선순위는 다음 순서다.

1. 집중할 과목·활동을 선택하고 시간을 기록하는 도구
2. 집중 중 스마트폰 딴짓을 방어하는 장치
3. 쌓인 집중·스크린타임 기록을 확인하고 비교하는 도구
4. 친구·그룹·리그를 통해 다음 집중을 자극하는 장치

신규 사용자가 가치를 처음 체감하는 순간은 실드가 앱을 막았을 때보다 **첫 세션을 마친 뒤 방금 집중한 시간이 선택한 과목의 기록으로 남는 것을 확인했을 때**로 본다. 첫 일주일의 활성화 목표는 긴 집중 한 번이 아니라 여러 날에 걸쳐 과목별 기록을 남기는 것이며, `가입 후 7일 내 집중 기록이 발생한 날수`·`첫 세션 이후 다른 날에 두 번째 세션을 시작한 비율` 같은 일별 기록 반복성을 우선 평가한다.

사용 단계는 **개인 가치 증명 → 소셜 가치 확장** 순서다. 다만 소셜 전환을 가입 며칠 후로 고정하지 않는다. 사용자가 기록할 이유를 아직 모르는 상태에서 친구 초대를 앞세우지 않는다는 것이 핵심이다.

## 제품 원칙

| 원칙 | 내용 |
| --- | --- |
| 자발적으로 시작하고 세션 중에는 확실하게 지킨다 | 기기 수준의 강제 통제는 하지 않는다. 사용자가 세션과 허용 앱을 정하면 세션 중 허용하지 않은 앱을 OS 수준 실드로 제한한다. 사용자는 언제든 세션을 종료할 수 있지만, 세션을 유지하면서 차단 앱만 즉석에서 우회할 수는 없다 |
| 의도적인 사용까지 나쁘다고 판단하지 않는다 | 집중 중 허용 앱과 하루 동안 줄이고 싶은 관리 대상 앱을 사용자가 직접 고른다. 줄이려는 것은 휴대폰 전체 사용시간이 아니라 사용자가 관리 대상으로 선택한 앱들의 합산 사용시간이다 |
| 사용자를 혼내거나 죄책감으로 통제하지 않는다 | 이탈을 의지 부족이나 실패로 규정하지 않는다. 실드·기록·캐릭터·소셜 기능은 과거에 세운 집중 의도를 다시 떠올리게 하는 장치다 |

역할 분담은 명확하다 — 집중 여부와 규칙을 정하는 결정권은 사용자, 정한 규칙을 세션 동안 유지하는 책임은 Gromo, 세션 종료와 규칙 철회 권한은 사용자, 실패에 대한 처벌은 없음.

**확인된 구현**으로서 현재 실드 정책은 다음과 같다: 허용 앱을 제외한 모든 앱을 차단한다, Safari·웹도 기본 차단하며 별도 허용 설정을 제공한다, 실드에 현재 집중 과목과 장착 캐릭터를 표시한다, 실드의 동작 버튼은 `닫기`다, 세션 종료 시 모든 실드 설정을 해제한다. Gromo는 알림 자체나 화면 점등을 차단한다고 주장하지 않는다.

## 핵심 사용자 흐름 요약

### 집중 세션 보호

`하단 중앙 집중 FAB → '무엇에 집중할까요?'에서 과목 선택 → 무제한·카운트다운·뽀모도로 중 타이머 방식 선택 → 세션 시작 → 허용 앱 외 앱에 실드 적용 → 차단 앱 실행 시도 시 과목명과 장착 캐릭터가 포함된 실드 노출 → 집중 복귀 → 세션 종료 후 집중시간 기록`. 현재 구현에서 세션을 먼저 구성하는 값은 시간이 아니라 **집중할 과목**이며, 선택한 과목은 세션 기록·실드 문구·Live Activity·과목별 통계에 이어진다.

### 하루 스크린타임 관리

`줄이고 싶은 앱 선택 → 일일 사용시간 목표 설정 → 선택 앱 합산 사용시간 자동 측정 → 목표 달성 여부 확인 → 친구·그룹원과 비교 → 스크린타임 챌린지·내기 참여 → 다음 날 목표와 행동 조정`. 측정 앱과 목표시간을 변경하면 당일 기록과 내기 결과가 왜곡되지 않도록 **다음 날부터 적용**한다.

### 집중과 스크린타임의 통합

| 집중시간 | 관리 앱 사용시간 | 해석 |
| --- | --- | --- |
| 증가 | 감소 | 가장 이상적인 행동 변화 |
| 증가 | 증가 | 집중도 했지만 무의미한 앱 소비도 증가 |
| 감소 | 감소 | 폰은 줄였으나 집중 행동으로 전환되지 않음 |
| 감소 | 증가 | 가장 우선적인 개선 필요 |

기존 집중 앱은 얼마나 공부했는지, 기존 스크린타임 앱은 얼마나 폰을 썼는지를 각각 보여준다. Gromo는 두 데이터를 함께 관리한다.

## 소셜 동기 구조 요약

| 관계 유형 | 주된 발견 경로 | 주된 가치 |
| --- | --- | --- |
| 리그에서 발견한 상위권 친구 | 리그·랭킹 | 요일별 집중량·과목 배분·폰 사용 패턴을 장기 관찰하는 비교 기준점 |
| 현실 친구·기존 스터디 | 초대 링크·기존 관계 | 챌린지·내기·함께 공부하는 재미 |

**리그와 친구.** 리그는 순위표가 아니라 장기간 참고할 사람을 발견하는 채널이고, 친구 신청의 일차 동기는 대화보다 상세 통계 열람이다. 친구 목록은 현재 목표에 맞게 갱신되는 비교 집합으로 본다. 확인된 구현으로, 타인 프로필에서 친구 여부·공개설정과 무관하게 닉네임과 친구 수·현재 티어와 리그 랭킹·오늘 집중시간·연속 집중 달성일·준비 시험을 항상 볼 수 있고, 공개 조건(본인 / 상대 `PUBLIC` / 상대 `FRIENDS`이면 친구 수락 후)을 충족하면 이번 주 요일별 집중시간·요일별 폰 사용시간·과목별 공부량 비교(오늘·이번 주·이번 달 탭) 세 카드가 열린다. 사용자 의도상 과목별 비교의 대표 기간은 최근 일주일이지만 현재 구현은 달력상 이번 주 기준이며, `최근 7일` 기본값은 개선 후보로만 둔다.

**그룹.** 그룹의 1차 대상은 익명 사용자가 아니라 이미 관계가 있는 현실 친구와 기존 스터디다. 공개 그룹 검색은 보조 경로이고 중심 유입은 초대 링크다. 그룹 채팅은 중심 기능이 아니다. 챌린지와 내기는 역할을 나눈다.

| 기능 | 역할 | 참여 강도 |
| --- | --- | --- |
| 챌린지 | 그룹 구성원이 부담 없이 참여하는 기본 공동 목표 (집중: 정해진 시간 이상 / 스크린타임: 선택 앱 합산 사용시간을 정해진 시간 이하로) | 낮음·일상적 |
| 내기 | 원하는 친구들만 시간조각을 걸어 경쟁 강도를 높이는 선택 레이어 | 선택적·강화형 |

스크린타임 내기는 모두가 같은 앱을 쓰는 공식 경쟁이 아니라 각자 관리하기로 정한 앱을 같은 시간 목표 이하로 쓰는 공동 자기관리 약속이다. 당일 조작을 막기 위해 측정 앱·목표 변경은 다음 날부터 적용하고, 당일 중간 측정값으로 성공을 조기 확정하지 않으며, 하루가 끝난 뒤 최종 사용량으로 판정하고, 참가비 차감과 정산은 서버가 관리한다.

<Callout label="후속 가설로 구분되는 것" tone="warn">
`콕 찌르기`와 콕 수신 후 즉시 집중 합류 루프, 그룹방의 실시간 집중 여부·현재 과목·시작시각 표시, 타인 누끼 캐릭터 공유는 초안이 **현재 완성 기능이 아니라 후속 제품 가설**로 명시한 항목이다. 현재 그룹방은 3열 멤버 타일에 기본 캐릭터·누적 순위·닉네임·누적·오늘 집중시간을 보여주며, 누끼 캐릭터는 최신 1장을 기기에 로컬 저장해 본인 화면(홈·집중·축하 모달·위젯·Live Activity·실드)에만 반영한다.
</Callout>

## 시스템 관점

앱은 React Native(Expo) 모노레포에 iOS 스크린타임 익스텐션을 포함하고, 서버는 Spring Boot(Java 17 + PostgreSQL) 백엔드다. 위 흐름에서 **OS 네이티브 계층**이 담당하는 것은 세션 중 허용 앱 외 차단(실드)과 선택 앱 사용시간 측정이고, **서버**가 담당하는 것은 세션 기록, 리그 랭킹·티어, 그룹, 챌린지 판정·내기 정산과 시간조각 같은 재화의 최종 정합성이다. 초안은 "참가비 차감과 내기 정산은 서버가 관리한다"고 못 박고, 판정은 하루가 끝난 뒤 최종 사용량으로만 한다. 서버 쪽 경계와 구현 단계는 [아키텍처 개요](/spec/architecture)에 있다.

| 제품 의도 | 집중 목표와 스크린타임 목표의 동시 달성, 개인 가치 증명 후 소셜 확장, 현실 친구 그룹의 동행감, 사용자 생성 캐릭터가 함께 집중하는 그룹 장면과 바이럴 |

초안이 남긴 검증 질문은 넷이다 — 상위권 비교가 비교 피로·자책으로 바뀌는 경계, `이번 주` 대신 `최근 7일`이 재방문과 다음 과목 선택에 더 도움이 되는지, 실시간 상태·누끼·콕 추가가 SNS 확인을 대체하고 즉시 합류율을 높이는지, 시험 준비생 집중 검증이 7일·28일 재방문을 높이는지. 출시 상태와 범위는 [범위와 로드맵](/spec/scope-roadmap)에서 이어진다.
