기획 심의는 제출 문서 한 편으로 끝나는 행사가 아니라, 저희가 4주 동안 쌓아 올린 서사를 낯선 다섯 명 앞에서 15분 만에 무너뜨려 보는 실험이었습니다. 결론부터 적으면 서사는 무너졌습니다. 05-29 심의에서 다섯 심사위원 중 셋이 같은 말을 했습니다 — "문제 제기는 디지털 디톡스인데 해법은 소셜앱이다." 06-05 자 공식 평가의견서도 같은 지적을 문어체로 반복했습니다. 그 뒤 2주 동안 저희가 실제로 바꾼 것은 발표에서 가장 크게 외쳤던 것들이 아니라, 아무도 묻지 않았던 화면과 재화 구조였습니다. 이 글은 무엇을 발표했고, 무엇을 지적받았고, 그중 무엇을 지라 티켓과 문서로 실제로 바꿨는지를 순서대로 복원합니다.

## 05-18 ~ 05-25 — 기획서를 14개 작업으로 쪼개다

05-18, 에픽 `GROMO-172` [기획·리서치] 기획 심의를 열고 그 아래 `GROMO-173` 기획 문서 작성을 둔 다음, 기획서의 목차를 그대로 서브태스크로 잘랐습니다. `GROMO-178`(목적 및 필요성)부터 `GROMO-193`(담당멘토 의견 받기)까지 14건입니다. 문서 한 편을 한 사람이 쓰지 않고 섹션 단위로 담당자를 박은 것은, 세 사람이 같은 문장을 서로 다르게 이해한 채 제출하는 사고를 막기 위해서였습니다. 실제 배분은 시장 분석·AI 활용 전략·개발 환경이 조재영, 주요 기능·추진 일정·수행 방법이 안XX(프론트엔드·iOS·디자인·마케팅), 시스템 구성도(인프라)·예상 문제·결과물 형태가 권XX(서비스 인프라·모바일)였습니다.

05-21 정규 멘토링에서 담당 멘토는 문서 자체를 문제 삼았습니다. "주요 기능이 너무 많다", "산문 글이 너무 많음 — 심사위원 피로도 생각", "TAM, SAM, SOM 근거 보충". 05-24 정규 멘토링에서는 더 날카로웠습니다. "왜 이 팀이 해야하는가가 없음", "핵심 결론이 우리의 결론이 아님 — 이게 답이면 다른 포레스트 앱에서 금방 따라옴", "나이를 좁힌 이유가 없으면 빼는 게 맞음". 이 두 번의 멘토링이 05-21 「기획서 초안」과 05-26 「최종 기획서」 사이의 차이를 만들었습니다. 초안의 프로젝트명은 `Otium`이었고 타겟은 "21\~24세 문과 계열 여성 취준생", 동기 장치는 "목표 실패 시 실제 인앱 재화 손실"이었습니다. 최종본에서는 이름이 `GroMo`로, 타겟이 "MZ세대 20대"로 넓어졌고, 손실 회피는 "재화 차감 페널티를 배제하고 완주자에게 보너스를 줘 기회비용을 자극"하는 구조로 뒤집혔습니다.

<Callout label="뒤집힌 판단 — 타겟을 넓힌 것" tone="warn">
멘토는 "타겟 반례 없게 좁히기"를 주문했는데 저희는 반대로 넓혔습니다. 좁힌 근거(문과·여성·21\~24세)를 대지 못했기 때문입니다. 심의에서 4번 심사위원은 정확히 이 지점을 "세분화된 랭킹은 좋은데 초기 마케팅이 너무 좁지 않겠냐"로, 평가의견서는 "세무사·공무원·수능·자격증 준비생처럼 일 단위 집중 목표가 명확한 사용자군으로 검증하라"로 되돌려줬습니다. 좁히라는 말과 넓히라는 말을 동시에 들은 셈이고, 이 기간에 저희는 어느 쪽도 근거로 결론 내지 못했습니다.
</Callout>

## 05-26 ~ 05-28 — 대본 두 벌과 예상 질문

05-26 회의에서 발표자를 조재영으로 정하고, 대본 초안 마감을 05-27 10시로 박았습니다. 회의록에 적힌 "발표때 중요하게 챙겨가야할 부분"은 세 줄이었습니다 — 빌드업 과정(왜 소셜, 왜 강제성 없는지), 다른 앱과의 차별성, 왜 소셜인지. 질문 대비는 "각자 five-whys 적극 활용, 본인만의 답안까지 우선 찾아오기"로 정하고, 담당 멘토들께 예상 질문 5개(비기술 3·기술 2)를 요청했습니다.

대본은 두 벌을 썼습니다. 05-26 「발표대본 - 암기 버전v1」과 05-28 「발표 대본 - 발표 버전」입니다. 암기본에는 발음 지시("무목적성 말고 발음 편하게")와 외울 한 문장이 섞여 있고, 발표본은 PDF 페이지 번호와 시간 구간이 붙은 15분짜리입니다. 두 대본이 공유하는 클로징 한 줄은 이것이었습니다.

> "집중할수록 외로워지는 디톡스가 아닌, 집중할수록 연결되는 디톡스."

05-28 「예상 질문 및 답안 대비」에는 7문항을 정리했는데, 실제 심의에서 나온 질문과 겹친 것은 거의 없었습니다. 저희가 대비한 것은 iOS 백그라운드 이탈 감지 구현, Screen Time API 심사 거절 사유, Flutter 대신 RN을 고른 이유 같은 기술 질문이었고, 심사위원들이 물은 것은 전부 기획의 전제였습니다. "그룹 기능이 유의미하게 작동할 사용자 최소치?" 항목은 답을 비워둔 채 제출됐습니다.

## 05-29 — 심의: 무엇을 발표했고 무엇을 들었나

발표 구조는 문제 → 실패 원인 → 차별점 → 일정의 4단 빌드업이었습니다.

| 구간 | 주장한 것 | 근거로 든 것 |
| --- | --- | --- |
| 문제 | 20대만 방치됨. 10대는 국가가 법으로 보호, 40·50대는 스스로 절제 | 4개 권역 정책 비교, 20대 하루 평균 6.3시간 = 연 3개월 |
| 실패 원인 | 자발적 디톡스는 FOMO 때문에 실패 — "끊고 싶지만, 끊으면 소외된다" | 타이머 금고·폴더폰·디톡스 카페 소비, 청소년 절반 이상이 디톡스 시도 경험 |
| 차별점 | 강제 차단이 아닌 실시간 소셜 동기화. 6개 기능을 3그룹으로 제시 | 강제 잠금의 장기 재발률이 높다는 2025년 대학 연구, Duolingo 30명 소그룹 리그 |
| 기술·일정 | Dual-Loop 설계, 멀티 클라우드, 스크린타임→마스킹→RAG→LLM 편지 파이프라인 | 7월 1차 MVP 출시 후 4개월 데이터 기반 PMF 검증 |
| 시장·BM | TAM $825M, SAM $160M, CAGR 18.4% | 프리미엄 구독 + 보상형 광고 |

돌아온 피드백은 발표의 1단(문제)과 4단(솔루션) 사이를 겨냥했습니다.

| 출처 | 지적 |
| --- | --- |
| 1번 심사위원 | 게이미피케이션과 사용량 추적으로 디지털 디톡스는 이뤄질 수 없다. 앱 내 리워드가 아니라 현실 세계 보상(예: ESG·탄소 감축)으로 풀어라. TV·PC·태블릿 중독은 커버되냐 |
| 2번 심사위원 | 1번에 동의. 랭킹은 좋고 동기도 생기니 더 고도화하라 |
| 3번 심사위원 (심사위원장) | 처음 제시한 문제 상황과 솔루션이 맞지 않는다. 기존 SNS 말고 새 SNS를 만든 느낌 |
| 4번 심사위원 | 우리 타겟은 자랑하고 싶은 사람인데 아예 안 보는 사람은 타겟이 아니다. 전체 디톡스가 아니라 "인스타 3시간 안 쓰기"처럼 좁혀라. 세분화된 랭킹은 좋으나 초기 마케팅이 좁다 |
| 5번 심사위원 | 후발주자는 못 따라가는데 어떻게 붙잡아 둘 거냐. 강제 잠금이 아닌 약한 제한이 더 효과 있다는 근거가 있냐 |
| 평가의견서 (등록 06-05) | "폰 하나로만 통제한다고 하면 다른 디바이스 통제 내용은 없음. 게이미피케이션으로 또 다른 중독을 만드는 것이 아닌가", "디지털 디톡스를 디지털로 보상한다는 것은 좋은 대안이 아님", "OS별 권한과 백그라운드 제한으로 실제 감지 가능한 범위가 달라질 수 있음 — 측정 가능한 행동 지표 중심으로 MVP를 설계하라" |

같은 날 정리한 팀 소감은 짧습니다. 권XX는 "다른 기기 제어 솔루션이 명확하지 않은 건 인정", 안XX는 "디지털 디톡스 워딩보다 다른 걸로 가져가야 할 것 같음", 저는 "빌드업 과정을 다시 가져가야 할 것 같다"로 적었습니다.

## 06-01 ~ 06-05 — 발표문과 다른 문서를 쓰기 시작하다

심의 다음 주 월요일부터 티켓이 다시 돌기 시작했습니다. 06-02 회의의 안건은 "데일리 스크럼 + 와프 + 기능 명세"였고, 결정은 두 줄이었습니다 — "각 화면별 기능 정의까지만", "색 제거". 같은 날 만들어진 「기능 명세 (Ver.2)」는 「최종 기획서」와 첫 문단부터 다릅니다. 기획서가 "게이미피케이션 기반 실시간 소셜 디지털 디톡스 앱"이었다면, Ver.2의 정의는 "스마트폰 사용을 강제로 차단하지 않고, 덜 쓴 시간을 보상으로 돌려주는 생산성 앱"입니다. '디지털 디톡스'라는 단어가 정의문에서 사라졌습니다.

Ver.2는 6개 기능 나열을 버리고 화면 단위로 다시 썼습니다 — 온보딩 O1\~O8, 홈, 집중 F0\~F3, 그룹·리그 G0\~G4, 상점 S0\~S2, 마이 M0\~M4. 그 과정에서 세계 랭킹은 폐기됐고, AI 하루 회고도 폐기돼 주간 편지 하나로 통합됐으며, 재화는 코인 단일에 현금 충전 불가·랜덤 희귀템 없음으로 못박혔습니다. 05-21 멘토링에서 나온 "낭비한 시간을 계속 띄워서 충격요법?"은 온보딩 O2·O5의 '남은 인생 시간' 1회성 연출로 들어갔습니다. 그리고 이탈 감지 항목에는 이런 자기 고백이 붙었습니다 — "백그라운드 측정·실시간 동기화는 기술 검증 필요." 평가의견서가 지적한 OS 제약을, 문서가 먼저 인정한 셈입니다.

이 시기 백로그가 무엇을 향했는지가 가장 정직한 증거입니다. 06-01\~06-12에 생성된 티켓 30건은 `GROMO-201` JWT 발급, `GROMO-202` 유저 기초 정보 저장, `GROMO-203` 포커스 타임 저장, `GROMO-206`·`GROMO-207` 재화 지급, `GROMO-213` 스크린 타임 목표 설정, `GROMO-221` 온보딩 화면, `GROMO-225` 게스트 로그인, `GROMO-227` 스크린타임 수집·p12 배포처럼 **개인 루프**에 몰려 있습니다. 발표에서 "결정적 차별점"이라고 말한 실시간 그룹 세션·주간 리그·갓생 공유 카드·LLM 캐릭터 편지에는 이 기간 티켓이 한 건도 없습니다.

## 06-05 ~ 06-12 — 평가의견서, 그리고 법률·심사로 축이 옮겨가다

06-05 `GROMO-244` "프로덕션 환경 준비하기 1차 - 나라별 개인정보 조사"가 열렸고, 그 결과가 06-11 「DB 저장 법률안 - 한국」, 06-12 「DB 저장 법률안 - EU」, 06-12 「APPLE 심사」 세 문서입니다. 한국 문서는 개인정보의 안전성 확보조치 기준 제5\~8조를 VPC·보안그룹·KMS·CloudWatch 보관 365일로 번역했고, EU 문서는 GDPR의 잊힐 권리(Soft Delete 유예 후 Hard Delete), 데이터 최소화, 백업의 EU 리전 제한, 동의 이력 분리 저장을 정리했습니다. 「APPLE 심사」는 네 줄짜리 체크리스트입니다 — 구매 복원, 테스트 계정 제공, OAuth가 있으면 Apple 로그인 필수, 자동 갱신 구독이면 무료 체험 제공.

06-12 정규 멘토링에서는 앱 심사 쪽 조언이 나왔습니다. "애플은 무조건 게스트 로그인이 되어야 함", "국가 스토어별로 로그인 분기 관리", 그리고 그룹 내기 기능에 대해 "플레이스토어에서 내기를 겜블링으로 인식하면 성인앱이 되어버릴 수도 있음". 같은 날 저희는 외부 멘토(법률)와 외부 멘토(기획) 세션 페이지를 개설했고, 실제 세션은 그다음 주(06-20·06-21)에 열렸습니다.

1. **평가의견서는 8월 중간점검용 숙제로 남았습니다.** 의견서 제목 자체가 "기획심의 의견서는 중간점검(8월)에 반영하여 개선해주시기 바랍니다"입니다. ESG형 현실 보상, 타 디바이스 통제, "왜 이게 디톡스인가"에 대한 답은 이 시기에 해결되지 않은 채 넘어갔습니다.
2. **06-13 「기능 명세 - MVP」** 로 범위가 한 번 더 깎입니다. 이 글의 마지막 날(06-12) 바로 다음 날이고, MVP 와 첫 애플 심사 이야기는 [다음 기록](/history/04-mvp-and-first-review)에서 이어집니다.
3. **법률·심사는 06-20·06-21 외부 멘토 세션에서 본격화됩니다.** 그룹 내기의 사행성(환전 가능성·우연성), 사용자 사진의 초상권·저작권, 신고센터 운영 의무가 여기서 정리되고, 06-29 `GROMO-550` 애플 심사 준비 및 제출로 이어집니다.
