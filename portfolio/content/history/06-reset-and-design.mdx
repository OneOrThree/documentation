중간 심의가 끝나고 9월 첫 주에 들어가면서, 팀은 기능을 더 얹는 대신 이미 만든 것의 뼈대를 다시 보기로 했습니다. 스프린트 12의 목표 이름이 「초.심.찾.기」였습니다. 그리고 2주 뒤인 09-12, 앱은 「같이숲」이라는 이름의 섬 세계관으로 45개 화면을 새로 세우고 있었습니다. 이 13일은 지금까지의 연대기 중 가장 짧은 구간이면서, 제품의 모양이 가장 크게 바뀐 구간입니다.

<Callout label="이 시기의 자료가 얇습니다" tone="warn">
9월 들어 컨플루언스에 새로 만들어진 페이지는 7개뿐입니다(활동비 1 · 정규 멘토링 4 · 팀멘토링 1 · 스프린트 12 회고 1). 9월 팀 회의록은 한 건도 없습니다 — 「팀회의」 폴더의 마지막 페이지는 「08-09」입니다. 스프린트 12 회고 페이지는 만들어졌지만 템플릿 문구와 빈 표만 있고 내용이 채워지지 않았습니다. 그래서 이 시기의 근거는 대부분 지라 티켓 본문과 멘토링 노트 4건입니다.
</Callout>

## 09-01 ~ 09-06 · 초심 찾기 — 스프린트 12

스프린트 12(08-30~09-06, 35건)에 들어간 일을 에픽으로 묶으면 초심의 정체가 드러납니다. 서버 아키텍처 리팩토링 9건, 문서 사이트 다이어그램 6건, 앱 UI 리팩토링 초안 3건, 안드로이드 기능 동등성 3건, 글로벌 출시 준비 3건, 그리고 에픽이 붙지 않은 정리성 작업 10건입니다.

"초심"은 새 기능이 아니라 **처음에 세우기로 했던 것들로 돌아간다**는 뜻이었습니다. 세 갈래였습니다.

- **문서를 다시 그린다.** 다이어그램 00~05(유스케이스·IA·유저 저니·서비스 아키텍처·시스템 아키텍처·클라우드 아키텍처)를 세 사람이 나눠 맡아 08-31~09-08 사이에 전부 채웠습니다(`GROMO-1648`~`GROMO-1653`). 문서 사이트 자체는 08-12의 `GROMO-1528`(팀 문서 저장소 documentation 구축)에서 시작해 08-30에 닫혔습니다.
- **서버 구조를 다시 잡는다.** 에픽 `GROMO-1643`(서버 아키텍처 리팩토링)이 08-30에 열렸고, 계층 정리·조회 계층 도입·순환 참조 제거·예외 규약 통일이 09-08~09-09에 차례로 닫혔습니다. 기술적 내용은 [패키지 경로가 계층을 말하게](/research/backend-layering-refactor)에 있습니다.
- **지라를 다시 센다.** `GROMO-1698`(지라 티켓 to 에픽 정리)과 `GROMO-1699`(Jira 에픽 타임라인 정리)가 이 스프린트에 들어갔습니다. 뒤엣것만 09-11에 닫혔고 앞엣것은 아직 「해야 할 일」입니다.

같은 주에 앱 쪽에서는 다국어(i18n) 전환이 끝났습니다(`GROMO-1704`, 4개 언어 + 언어 설정 화면, 09-06 완료). 09-02 하루에 글로벌 출시 준비 후속 티켓 9건이 한꺼번에 열렸습니다 — 과목 코드화, 네이티브 문구 번역 사전, iOS 권한 팝업 다국어, 리그 그룹을 직업 코드 + 국가로 분리 등입니다.

## 09-05 ~ 09-08 · 멘토링 사흘이 방향을 틀었다

**09-05, 담당 멘토(정규 멘토링).** 마일스톤으로 "UI 멘토링을 받아라"가 가장 먼저 적혔습니다. 그리고 제품 쪽 지적이 붙었습니다. "캐릭터가 있고 나도 보이고 상대방도 보이고 서로에게 동기부여가 되면 좋겠다", "집중이라는 게 서로를 감시하는 건 아니지만 서로 공부를 하고 있다는 느낌을 줘야 한다. 이걸 UI로 풀어야 한다." 수익 쪽으로는 "게임과 다르게 플랫폼은 헤비 유저가 없다. 유저당 낼 수 있는 돈은 정해져 있다"며 익명 교류에서 과금이 나오는 구조를 예로 들었습니다. 일정도 이때 못박혔습니다 — "이번 주 금요일에는 기획 + 레이아웃 + 뷰의 구조 정도는 있어야 한다."

**09-06, 정규 멘토링(기술).** 다른 주제였습니다. 출시된 앱의 평점이 3.7이라는 점, i18n을 넣었다면 location·timezone·RTL까지 봤는지, 그리고 "AI가 하기 어려운 것들을 찾아야 한다"였습니다.

**09-08, 팀 멘토링(아키텍처·사업).** 세 가지가 남았습니다. (1) "국내 검증하고 글로벌은 나중에 나가는 게 좋다" — 불과 엿새 전 09-02에 글로벌 티켓 9건을 연 판단과 정면으로 부딪칩니다. (2) 최종 심의에서 필요한 건 기능 확장이 아니라 고도화이고, 비중은 "기술 3, 돈 되는 이야기 7"이라는 것. (3) 배포 절차 지적 — dev로 머지할 때 iOS·안드로이드·OTA가 전부 섞여 들어가 체리픽이 안 되니, 커밋에 `[ios]` `[android]` `[ota]` 마크를 붙이라는 것이었습니다.

같은 주 09-07에 `GROMO-1718`(UI 멘토링 멘토 잡기)이 열렸고 09-13에 닫혔습니다. 09-05의 첫 줄이 티켓이 된 셈입니다.

## 09-07 ~ 09-10 · 디자인 스프린트 — 세 안을 만들고 하나로 줄이다

스프린트 13(09-07~09-14)의 목표 이름은 그냥 「디자인」입니다. 첫날 열린 티켓 세 건이 이 스프린트의 성격을 그대로 보여줍니다 — `GROMO-1715` / `1716` / `1717`, 「기획 + 와이어프레임 + 컨셉아트」를 조·권·안 각자 한 건씩. 세 사람이 같은 문제를 따로 풀어 세 안을 만드는 방식이었습니다.

**09-09, 담당 멘토(정규 멘토링) 3안 리뷰.** 노트가 사람별로 나뉘어 있습니다.

| 안 | 받은 평 |
| --- | --- |
| 권태화 안 | "아트 스타일 좋음… 같은 공간은 있는데, 같이하는 느낌은 아니다." 캐릭터 하나하나가 인지되지 않고, 각자 다른 행동을 해도 문제없어 보여 공통 목표가 없다. 색감은 셋 중 제일 좋았다 |
| 안수빈 안 | "광장이 왜 있는지 모르겠다." 섬에서 어떻게 집중을 유도할 것인가가 비어 있다 |
| 조재영 안 | "모닥불 ≠ 공부하는 공간, 쉬는 공간이 더 익숙하다." 섬을 키우는 성장이 중요해 보이는데 세계관이 더 필요하고, 길드 개념처럼 보인다 |

결론은 한 줄이었습니다. **"UI는 안수빈 것을 가져가고, 나머지는 소재 테스트로."** 그리고 방향 지시가 붙었습니다 — "기능을 감성으로 푸는 걸 해봤으면 좋겠다", "감성이 없으면 기능이 효율적인 곳으로 간다. 앱에서 감성은 아트와 소셜밖에 없다", "동물 세계관이고, 배가 있고, 배도 뗏목·돛단배 이런 컨셉이어야 한다." 같은 자리에서 AI 실시간 모더레이션은 보류 쪽으로 밀렸습니다 — "AI 모더레이션이 실패한다면? 그게 더 어색하다." 신고 이후 1차 판정용으로만 쓰자는 쪽입니다.

일정도 이 노트에서 나왔습니다: 1차 기획은 09-19~20까지, 추석 전에 1차를 점검하고, 2차를 만들어 9월 말까지, 1차 빌드는 10월 16일쯤.

이 리뷰 직후 09-09~09-10에 `GROMO-1721`·`1722`(디자인 상황 보고), `GROMO-1728`(새로운 디자인 유저 저니 다이어그램), `GROMO-1730`·`1731`·`1732`(기획 검토 3·4·7번)가 연달아 열리고 닫혔습니다.

## 09-10 ~ 09-13 · 같이숲 — 45화면, 계약 66종, 이벤트 14종

09-10 밤 `GROMO-1736`의 본문에 제품의 새 이름이 처음 문서로 박힙니다. **같이숲**입니다. 티켓은 "같이숲 IA 확정본의 45화면(본화면 35 + 보조시트 9 + 공동장소 1)을 앱 안에 전부 세운다. 일부만 골라 만드는 게 아니라 전체를 재생성한다"고 적고 있습니다. 화면 구획은 온보딩·마을/집중·섬 운영·게시판·전망대·우체국·항구·프로필/상점·공동장소·시트이고, 건물은 7채(마을회관·모닥불·게시판·오두막·전망대·우체국·항구)로 확정됐습니다. 서버는 붙이지 않고 전부 목데이터, 밤에 AI를 돌려 한 번에 뽑는 작업이라 "화면 하나하나의 완성도보다 45개가 전부 서고 빌드가 깨지지 않는 것이 우선"이라고 명시돼 있습니다. 09-11에 완료됐습니다.

같은 날 `GROMO-1739`(구현한 화면별 API 스펙 정리)가 69화면 / 66계약 / 14이벤트 규모의 스펙 v0.3을 만들었고, 09-11 밤에 그것을 받는 에픽 두 개가 생겼습니다.

- **`GROMO-1748`** — 같이숲 API 기반: 접두어 없는 경로, `{data}` 응답 봉투, 오류 코드, 멱등성, 낙관락, 커서, business-api → data-api 내부 호출 골격, `server/chat` → `server/realtime` 개명과 섬 실시간 14종, 화면 단위 집계 13종. 자식 10건.
- **`GROMO-1749`** — 같이숲 도메인 계약 66종을 14개 기능 묶음으로 나눠 구현. 묶음마다 설계 문서 PR 1건 + 구현 PR 1~2건. 자식 28건.

먼저 닫힌 것은 공통 규약이었습니다. `GROMO-1750`(공통 API 계약 설계)의 본문이 이유를 적고 있습니다 — "지금 오류 봉투가 세 갈래로 갈려 있다. 여기서 통일하지 않으면 나머지 37개 티켓이 각자 자기 봉투를 만든다." 09-12에 PR #738로 머지됐습니다. 이어서 섬 실시간 이벤트 14종 설계(`GROMO-1754`), `server/chat`을 `server/realtime`으로 개명(`GROMO-1755`), 섬 건설·공용 음악·화면 집계 설계가 09-12에 닫혔습니다. 09-12 밤 `GROMO-1794`에는 "「realtime」이 무엇을 하는 서비스인지 드러내지 못한다"며 방금 지은 이름을 재검토하는 티켓이 다시 열립니다.

**09-12, 담당 멘토(정규 멘토링) — 피그마를 띄워놓고 한 회의.** 세계관이 구체화되자 질문이 더 날카로워졌습니다. 노트에 남은 것 중 몇 개: "집중이 낚시밖에 없는가? 집중할 때는 바다 낚시로 푸는 게 개연성은 있다. 그런데 개인이 낚시하는 건 개인의 치장이므로, 그룹에서는 섬에 기여하는 방향으로 수정해야 할 것 같다." "섬의 장이 왜 섬에서 그룹을 유지해야 하는지 모르겠다." "섬마다 컨셉이 잘 드러나야 한다." 마지막에 최종 질문 네 개가 남았습니다 — 집중과 동기부여, 이 집중이 어떻게 동기부여로 이어지는가, 어떻게 섬에서 작업을 하도록 유도할 것인가, 섬에 들어온 사람이 빠져나가지 않게 하려면 어떻게 할 것인가.

## 섬 세계관 — 어디까지 결정됐나

| 결정된 것 | 아직 결정되지 않은 것 |
| --- | --- |
| 세계관 전환 자체 — 「같이숲」, 섬 · 배 · 동물 컨셉 | 집중 행위를 낚시로 푸는 것이 맞는지 (09-12 노트에 "낚시를 어떻게 풀어내야 할지 모르겠다") |
| UI 기준안은 안수빈 안, 나머지 두 안은 소재 테스트로 | 개인 낚시(치장)와 섬 기여(그룹)를 어떻게 잇는지 |
| IA 45화면(본화면 35 · 보조시트 9 · 공동장소 1)과 건물 7채 | 섬장이 섬을 유지할 동기 · 섬마다 컨셉을 드러내는 방법 |
| 화면별 API 스펙 v0.3 — 69화면 / 66계약 / 14이벤트 | 섬을 누구나 만들 수 있게 할지(어뷰징), 인원 제한·강퇴 정책의 세부 |
| 공통 API 규약(경로·봉투·오류·멱등성·낙관락·커서) 머지 완료 | NPC(앵무새)가 행동을 푸시하는 연출을 넣을지 |
| AI 모더레이션은 실시간이 아니라 신고 후 1차 판정으로 | 연령·성별 등 신원 확인을 어디까지 요구할지 |
