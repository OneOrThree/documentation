## 9월 19일 — 개인 보상에서 섬 공동 재화로

같이숲의 모든 새 재화는 섬 통장으로 귀속시키고, 개인 지갑은 테이블만 남겨 둔다는 정책을 정했다. 상품 가격이 없을 때 0원 구매로 처리하지 않고 구매를 막기로 했다. 실시간 사건 전달은 HTTP를 기본으로, Kafka를 선택 경로로 두며 양쪽을 `eventId`로 중복 제거한다. 이때의 수신 200은 STOMP 화면 발행까지 끝났다는 뜻이 아니었다.

## 9월 20일 — 집중 적립과 응원 자격

분당 보상은 UTC 하루 상한으로 묶되 배치가 돈 시각이 아니라 분이 완성된 시각의 날짜에 넣는다. 강퇴 전에 섬 통장으로 지급된 보상은 되돌리지 않는다. 원장은 분당 행을 남기고 가계부 조회에서만 묶는다. [ADR-035](/adr/adr-035-village-economy-boundaries)에 선택과 기각안을 정리했다.

휴식 중 응원 발신은 허용하되 Redis presence가 최종 자격을 판정하지 않도록 바꿨다. 발신 검증에 이미 사용한 Data의 현재 집중 주민 집합으로 수신자를 정했다. 초기 구현의 "presence 키가 있으면 충분하다"는 판단과 STOMP 헤더 전달 방식은 리뷰 후 뒤집혔다. [ADR-036](/adr/adr-036-realtime-authority)에 남겼다.

## 9월 21~22일 — 병합 순서가 설계의 일부가 되다

병렬 작업은 Flyway 마이그레이션 번호를 디스패치 때 예약해도 앞선 PR의 머지 순서가 바뀌면 다시 번호를 맞춰야 했다. 병합 직전 main의 최대 번호를 확인하고 파일명뿐 아니라 테스트·문서의 참조도 함께 옮기는 규칙이 나왔다. 테스트가 Flyway 자체를 실행하지 않는 경로도 있어 마이그레이션 병존 검증을 별도로 했다.

CI가 초록색이어도 필요한 잡이 아예 트리거되지 않으면 검증 완료가 아니다. `generate-docs`만 실행된 PR은 서비스별 테스트 잡을 다시 확인했다. 병합 트리에서 한꺼번에 난 118건 실패는 코드 결함이 아니라 Docker 자원 고갈로 분류해 Data API 전체 테스트를 워크트리 전체에서 한 번에 하나만 실행했다. 충돌 마커를 기록만 하고 제거하지 않아 main까지 간 사례도 있었고, `git add -A` 전에 마커를 검사하는 절차를 추가했다. 이 사건들은 `phone/doc/parallel/sprint15-2026-09-20/decisions.md` N20~N34에 남아 있다.

## 9월 23일 — 배포와 계약 정리

2.0 iOS 빌드 4~7을 TestFlight에 업로드했다. 서버에서는 공개 오류 상태/내부 장애 로그와 공개 DTO/내부 전송 DTO 경계를 나눴다. 공개 OpenAPI의 동명 스키마가 다른 도메인 필드를 가리키는 오류도 찾아 별도 PR로 교정했다. [배포·API 기록](/operations/05-september-23-release-and-api-boundaries)은 업로드, 머지, 배포를 구분해 놓았다.

이 주의 역할 분담은 [팀 역할](/team/roles)에 반영했다. 8월 누적 PR 비율을 9월의 새 제품 작업량으로 읽지 않도록 기준일을 분리했다.
