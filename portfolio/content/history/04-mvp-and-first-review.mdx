기획서를 통과시킨 팀이 처음 배운 것은 "기획서에 쓴 기능이 OS 가 허용하는 기능과 다르다"였습니다. 5주 동안 릴리스를 여섯 번 냈고(`환경 세팅`·`0.0.2`~`0.0.6`), 그 사이에 MVP 범위는 네 번 줄었습니다. 가장 값비싼 축소는 멘토가 시켜서가 아니라, 6월 4~5일 이틀과 6월 25일 하루에 우리가 직접 확인한 API 제약에서 나왔습니다.

이 기록에서 멘토는 실명 대신 역할로 적습니다 — 담당 멘토(정규 멘토링), 정규 멘토링 멘토(제품), 정규 멘토링 멘토(인프라·프로세스), 외부 멘토(기획), 외부 멘토(법률).

## 05-31 ~ 06-07 빌드 0.0.2, 그리고 빈 화면 이틀

스프린트 4(05-31~06-09)의 목표는 두 줄이었습니다 — "빌드 0.0.2 + 마스코트 선정". 앞의 절반만 됐습니다.

릴리스 `0.0.2`는 06-07에 27건으로 닫혔습니다. JWT 발급(`GROMO-201`), 유저 기초 정보 저장·변경, 포커스 타임 저장과 그에 따른 인게임 재화 지급, 온보딩 화면(카카오 로그인 + 게스트 로그인), 그리고 `.p12` 파일을 뽑아 팀원 기기에서도 iOS 개발 빌드가 되게 만든 작업(`GROMO-227`·`GROMO-243`)이 들어갔습니다. 06-02 「데일리 스크럼 겸 회의」에서 정한 API 개발 순서가 그대로 티켓이 됐습니다 — 유저 기초 정보 → 포커스 모드 시간 → 얼마 벌었는지 → 기초 정보 변경.

같은 주에 스크린타임 API 가 막혔습니다. 06-04~06-05 이틀 동안 `DeviceActivityReport` 차트 영역이 끝까지 완전히 빈 화면이었습니다. 컨플루언스 「조재영-스크린타임 API 트러블슈팅」에 가설 12개를 시간순으로 남겼습니다. 필터가 빈 토큰이라서, 차트 라이브러리 때문에, `List` 안이라 좌표공간이 충돌해서, 익스텐션 캐시가 낡아서 — 여덟 번째까지 전부 아니었습니다. 진짜 원인은 Report 익스텐션 타겟을 `project.pbxproj` 를 손으로 편집해 추가하는 바람에 구식 `NSExtension` 방식으로 등록됐다는 것이었고, Xcode 마법사로 타겟을 다시 만들자 해결됐습니다.

<Callout label="빌드는 항상 성공했다" tone="warn">
이 실패가 이틀을 먹은 이유는 세 가지였습니다. ① 같은 앱의 Monitor 익스텐션은 정상 동작해서 서명·앱그룹·권한은 멀쩡하다고 믿었고(실제로는 Monitor 만 구식 방식이 맞고 Report 만 ExtensionKit 이어야 하는 비대칭이 핵심), ② `xcodebuild` 는 잘못된 임베드 방식을 에러로 잡지 않아 **빌드가 항상 성공**했으며, ③ 가짜 엔타이틀먼트·불안정 필터·잘못된 등록 세 문제가 겹쳐 하나를 고쳐도 증상이 안 사라졌습니다. 이때 "데이터·뷰를 의심하기 전에 익스텐션 프로세스가 실행되는지부터 가른다"를 규칙으로 적어뒀습니다.
</Callout>

마스코트는 선정되지 않았습니다. 5월에 3D 캐릭터 쪽으로 파봤던 것(`GROMO-145`·`GROMO-151`, Expo + expo-gl + Three.js)은 06-06 「앱에서 캐릭터 구현하는 방식」에서 "복잡한 애니메이션이 필요한 게임이 아니라 단순한 동작이 주"라는 이유로 Lottie + SVG 쪽으로 판정이 뒤집혔고, 캐릭터를 실제로 정의하는 티켓(`GROMO-398`)은 06-22 에야 생겼습니다. 스프린트 목표에 적힌 두 항목 중 하나가 3주 밀린 셈입니다.

06-08 스프린트 4 회고에서 나온 합의는 제품이 아니라 규율이었습니다 — 지라 티켓 필드를 최대한 다 채우기, 업무 연관관계 설정하기, "보고자 == 검토할 사람"으로 두고 검토 → 완료로 넘기기, DoD 정비.

## 06-08 ~ 06-14 MVP 를 '완료·진행·예정' 세 칸으로 쪼개다

스프린트 5(06-08~06-14)는 조회되는 티켓이 5건뿐인 짧은 주였습니다. 릴리스 `0.0.3`(06-15, 5건)의 설명은 "스크린 타임 기능 추가" 한 줄이고, 실제로 들어간 것도 「스크린 타임 구현」(`GROMO-248`)과 그 하위의 화면 추가·RN 리포트 띄우기·홈 총 사용시간 표시가 전부입니다.

대신 이 주에 범위가 처음 공식적으로 줄었습니다. 06-13 「기능 명세 - MVP」는 06-02 의 「기능 명세 (Ver.2)」를 **완료 / 진행 / 예정** 세 칸으로 다시 나눈 문서입니다. 완료 칸에는 타이머, 장착/해제(목 데이터), 카카오·게스트 회원가입만 남았고 — 멀티플레이, 상점, 결제, AI 피드백 칸은 완료·진행 모두 비어 있습니다. 그룹 내기, 그룹 생성, 콕 찌르기, 리그, 나라별 랭킹, 월 구독, 유료 에셋, AI 통계 리포트가 전부 '예정'으로 내려갔습니다.

같은 날 정규 멘토링 멘토(제품)의 말이 이 분할을 밀었습니다. "mvp 에 그룹 기능만 넣는 것도 오키", "일단 내고 생각해라". 워딩도 이때 바뀌었습니다 — "디지털 디톡스가 아니라 숏폼(집중력을 흐트리는) 쪽으로", "워딩은 스마트폰에 한정되게". 다음 날 06-14 정규 멘토링 멘토(인프라·프로세스)도 같은 방향으로 더 세게 밀었습니다. "디지털디톡스 워딩을 안 쓰는 것도 좋은데, 디지털디톡스 단어가 생각나게 하는 것도 안 됨", "기술적인 난이도가 높지 않다는 평을 들으면 안 됨". 기획 심의 피드백을 체크리스트로 만들자는 제안도 여기서 나왔습니다.

06-12 에는 「APPLE 심사」 페이지가 네 줄짜리 체크리스트로 생겼습니다 — 구매 복원 기능 필수, 로그인이 있으면 심사용 테스트 계정 제공, OAuth 가 있으면 Apple 로그인 필수, 자동 갱신형은 무료 체험 제공. 이 중 세 번째가 곧바로 06-14 의 「애플 로그인 API 구현」(`GROMO-274`)으로 이어졌습니다. 같은 날 담당 멘토도 "애플은 무조건 게스트 로그인이 되어야 함", "국가 스토어별로 로그인 분기 관리"를 지적했습니다.

그리고 06-13 에 「스크린 타임 API 심사」(`GROMO-252`)를 열었습니다. Family Controls **Distribution 엔타이틀먼트 신청**입니다. 06-22 에 완료로 닫혔습니다.

## 06-15 ~ 06-21 MVP 기능 개발 1주차 — 83건짜리 릴리스

스프린트 6(06-15~06-21)의 목표는 "MVP 기능 개발 1주차"였고, 조회되는 티켓 77건 중 67건이 릴리스 `0.0.4`(06-21, 83건)로 들어갔습니다. 이 한 주가 이 시기 전체에서 가장 밀도가 높습니다.

- **인증** — 애플 로그인 API·화면, 게스트 로그인, 로그아웃, 회원 탈퇴(`GROMO-274`~`GROMO-277`, `GROMO-307`~`GROMO-312`)
- **그룹** — 생성·목록·검색·개요·참가·탈퇴·정보·설정·공지·챌린지까지 API 12종과 화면(`GROMO-278`~`GROMO-290`, `GROMO-313`~`GROMO-327`)
- **실시간** — 그룹 포커스 Presence STOMP(`GROMO-291`), 채팅 이력 조회 REST(`GROMO-293`), 상태 스냅샷(`GROMO-295`). 이 경로의 설계 판단은 [WebSocket은 왜 혼자 확장이 안 될까](/research/chat-fanout)에 있습니다(06-18).
- **구조 정리** — 전 엔티티 PK 를 `Long` → `UUID` 로 전환(`GROMO-360`), 패키지를 레이어별에서 도메인별로 재편(`GROMO-361`), `@LoginUser` ArgumentResolver 로 인증 유저 ID 주입 통일(`GROMO-363`), 예외를 `ErrorCode` enum 으로 일원화(`GROMO-364`), 타임존·시간·날짜 표준화(`GROMO-346`)

06-14 「06-14 IA」와 06-18 「06-18 IA 2차」에서 그룹의 규칙을 정했습니다 — 참여 인원 10명 제한(더 비싼 BM 에서 확장), 그룹장이 생성 시 설정한 것을 모두 변경 가능, 총 집중 시간 기준 그룹원 랭킹. 2차 회의에서는 "그룹 목록의 어디에서 외부 방 리스트가 보이게 할 것인가", "그룹 내기 CRUD 당일 삭제 금지?" 같은 미해결 질문만 남았습니다.

같은 기간에 지식 관리 쪽도 갈아엎었습니다 — [지식이 세 번 흩어졌다 다시 모였다](/research/knowledge-harness)(06-15).

06-20 외부 멘토(법률) 세션에서 내기 기능의 경계가 정해졌습니다. 도박 판정의 두 축은 **환전 가능성**과 **우연성**이고, 결론은 "환전 가능성은 완전히 없애고 우연성도 명확히 배제한다"였습니다. 달성 비율로 보상을 다르게 주는 것은 괜찮지만 확률은 안 됩니다. 사용자가 찍은 사진을 캐릭터로 쓰는 아이디어에는 초상권·저작권·음란물 세 갈래 제약이 붙었고(신고 센터 운영, 신고 시 즉시 중지, 소명·반박 절차), 스크린타임 데이터는 "닉네임(가명)만, 고정 아이디는 실명 취급"이라는 원칙이 붙었습니다.

06-21 두 멘토링은 같은 곳을 찔렀습니다. 외부 멘토(기획)는 "디톡스랑 소셜 둘 다 가져가려 한다, 디톡스 빼고 소셜로 가라"고 했고, 담당 멘토는 "앱 UI/UX 자체가 별로인 것 같다, 플로우는 이해가 가는데 각 기능이 이해가 안 간다 — 너무 내용이 많다"고 했습니다. 이벤트 로그를 서버용과 유저용으로 분리하라는 지적도 여기서 나왔고, 그 결과가 `GROMO-384`(유저 로그·서버 로그 분리, 전용 Logger)입니다. 그 PR 한 건에서 나온 함정 다섯 건은 [로깅이 비즈니스를 깨뜨리다](/research/logging-traps)에 있습니다(06-25).

## 06-22 ~ 06-28 할 수 있는 것의 경계를 문서로 못 박다

스프린트 7(06-24~07-05, 53건)과 릴리스 `0.0.5`(06-28, 37건)의 성격은 '구현'보다 '확정'입니다. IA 확정(`GROMO-386`), Application Architecture(`GROMO-387`), System Architecture(`GROMO-388`), 푸시 알림 발송 상황 정의(`GROMO-391`), OKR 설계(`GROMO-464`), 그리고 온보딩 O1~O8·집중 F0~F2·리그·친구·설정 화면 디자인이 한꺼번에 티켓이 됐습니다.

이 시기의 진짜 분기점은 06-25 하루에 나온 문서 두 편입니다.

「스크린타임 기능 구현 가능 범위」는 "이 기능 되나요?"를 한 장으로 판정합니다. 핵심은 iOS 가 수치를 아는 쪽과 쓸 수 있는 쪽을 일부러 갈라놨다는 것입니다.

| 익스텐션 | 사용량 수치 접근 | App Group 쓰기 |
| --- | --- | --- |
| Report (`screentimereport`) | 가능 | **불가**(OS 샌드박스) |
| Monitor (`GromoScreenTimeMonitor`) | 불가(콜백만) | 가능 |
| 메인 앱 (`gromo`) | 불가 | 가능 |

**수치를 아는 쪽은 못 쓰고, 쓸 수 있는 쪽은 수치를 모릅니다.** 그래서 "오늘 5시간 23분 썼음"을 서버로 보내는 경로가 없습니다. 문서는 세 가지를 명시적으로 포기·채택했습니다.

- **포기**: 정확한 분 단위 사용시간의 서버 전송. Report 익스텐션의 `FileManager` 우회는 "Apple 이 일부러 봉인한 수치를 뚫는 행위"라 App Review 2.5.1 리스크와 "iOS 업데이트로 구멍이 막히면 기능이 조용히 깨짐" 때문에 비권장으로 적었습니다.
- **채택**: 목표 달성 O/X(boolean) 전송, 그리고 더 필요하면 **30분 버킷** — 하루 스케줄 1개에 30분 간격 threshold 를 박고 어느 눈금까지 발화했는지로 사용량을 역추적하는 방식. Monitor 익스텐션은 App Group 쓰기가 공식 허용된 쪽이라 프레임워크를 의도대로 쓰는 정석 경로입니다.
- **불가 확정**: 실시간으로 "지금 무슨 앱을 쓰는지" 조회, 그리고 **순수 화면 점등(pickup) 감지**. 후자 때문에 "a~b 시간대 폰 안 보기" 챌린지는 "앱을 열어서 사용했는지"로만 판정할 수 있고, 화면만 켠 건 거짓 성공이 됩니다.

같은 날 「IOS 익스텐션, 엔타이틀먼트 현황판」은 이 판정을 발급 작업으로 번역했습니다. 당시 타겟은 셋(메인 앱·Monitor·Report)이었고, 푸시(`aps-environment`)·Associated Domains·Shield 익스텐션 2종·Widget 을 추가하려면 App ID 신규 등록과 **dev·distribution 프로비저닝 프로파일 양쪽 재발급**이 필요하다고 못 박았습니다("한쪽만 하면 개발 빌드는 되지만 TestFlight 빌드에서 깨짐"). 이 요청이 `GROMO-445`(요청)와 `GROMO-453`(발급)으로 갈라져 티켓이 됐습니다.

<Callout label="제약이 제품을 바꾼 자리" tone="primary">
6월 초 「기능 명세 (Ver.2)」는 "그룹원 방을 타일로 붙여 실시간 상태를 본다", "앱 이탈을 실시간 감지한다"를 전제로 쓰였습니다. 문서 안에도 이미 물음표가 붙어 있었습니다 — "백그라운드 측정·실시간 동기화는 기술 검증 필요.?? 아마 안될거같기도". 06-25 판정으로 그 물음표가 답을 받았습니다. 이탈 감지는 RN `AppState` 로 "떠났다/돌아왔다"와 나가 있던 시간까지만, 사용량 공유는 O/X 또는 30분 버킷까지만. 06-24 「푸시 알림 트리거 명세」가 "목표 사용시간 초과 경고"만 서버 푸시가 아니라 **iOS 로컬 알림**으로 뺀 것도 같은 이유입니다 — 서버는 실시간 사용량을 모릅니다.

06-24 담당 멘토 세션에서 한 문장이 남았습니다. "가설이 뭔가? 세운 가설이 없음. A/B 테스트도 PRD 도 모두 가설이다." 그리고 리그와 소셜을 분리해서 봐야 한다는 지적 — "소셜은 같은 카테고리의 애들이 뭘 하는지 공유하는 것, 경쟁은 내가 어느 위치에 있는지 알고 싶어하는 것. 즉 우리의 가설은 경쟁이다(리그는 경쟁 기능이다)". 06-25 기획 회의에서 팀은 그럼에도 리그에 소셜을 붙이기로 하고(친구 관계, 핀 설정, 티어 배지, 친구가 되어야 상세 통계 열람), 티어 5단계 이름을 확정했습니다.

## 06-29 ~ 07-05 '첫 애플 심사' 스프린트

스프린트 8(06-29~07-05)의 목표는 한 단어였습니다 — "첫 애플 심사". 시작일 하루에만 티켓 40건이 생겼습니다.

빌드 경로부터 갈아탔습니다. `GROMO-515`(06-29)에서 **EAS 빌드를 제거하고 로컬 fastlane TestFlight 배포로 전환**했습니다. 07-04 「배포방식」 페이지가 이유를 적고 있습니다 — 현재는 로컬 빌드 → TestFlight 이고 이 구간은 자동화가 불가능하며(자동화하려면 월 단위 비용이 붙는다는 계산), 다만 TestFlight → 심사 제출 구간은 이미 보유한 ASC API 키로 자동화할 수 있다는 것이었습니다. 프로비저닝 갱신 절차는 06-19 「expo 배포 관련 대응 리스트」에 케이스별로 정리해뒀습니다.

「애플 심사 준비 및 제출」(`GROMO-550`)은 06-29 에 생겼습니다. 완료 조건은 "App Store Connect 빌드·메타·스크린샷·개인정보 완비, 심사 제출". **이 티켓이 닫힌 날은 07-09 입니다.** 스프린트 8 의 종료일(07-05)을 나흘 넘겼습니다.

07-05 까지 나간 마지막 릴리스는 `0.0.6`(6건)이고, 내용은 프로비저닝 갱신, 이탈 감지·푸시, 집중 세션 중 허용앱 설정과 다이나믹 아일랜드, 금지앱 접속 시 쉴드 스크린, 로그인 불가 버그(`GROMO-577`), 그리고 Actuator + micrometer 관측 수집층(`GROMO-588`)입니다.

07-05 정규 멘토링 멘토(제품)의 평가는 냉정했습니다. "초기에 차별점이 지금은 안 보인다. 다른 앱들과 차별점이 안 보이는데, 뭘 MVP 로 검증하려고 하는가?" 구체적 지시는 여섯 가지였고 — 온보딩을 지금의 절반으로, 리그를 숫자만이 아니라 그리드+프로그레스 바로, 내 행이 최상단 고정, "어제보다 몇 시간 더 했다"를 알림으로 — 전부 다음 시기의 작업이 됐습니다.

심사 제출 직전 QA 가 07-06~07-07 이틀에 몰렸습니다. 버그 티켓 27건이 이 스프린트에 달렸고, 성격이 두 갈래로 갈립니다. 하나는 **데이터 유실 계열** — 강제 종료 세션의 서버 업로드 실패로 집중 기록 영구 유실(`GROMO-613`), 업로드 실패 시 재시도 없음(`GROMO-614`), 온보딩 완료 플래그가 서버 등록 성공 전에 저장되어 서버-로컬 영구 불일치(`GROMO-617`). 다른 하나는 **날짜·집계 계열** — 1분 미만 자투리 초가 오늘 집계에서 0 으로 누락(`GROMO-642`), KST 오전 9시 이전 세션이 UTC 날짜 경계 때문에 오늘 집계에서 누락(`GROMO-643`). 뒤쪽은 이때 한 번 막았다가 7~8월에 [타임존 버킷 전쟁](/research/timezone-wars)으로 다시 돌아옵니다.
