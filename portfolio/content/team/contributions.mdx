## 왜 커밋이 아니라 담당자인가

우리 팀은 Claude 계정을 공유해서 씁니다. 그래서 **git 커밋의 작성자가 실제 담당자와 다를 수 있습니다.** 누구 자리에서 세션을 돌렸느냐에 따라 커밋 author가 정해지는 구간이 있고, 커밋을 세면 그 왜곡이 그대로 비율에 들어갑니다.

담당자는 왜곡되지 않습니다. GitHub PR의 assignee와 지라 티켓의 assignee는 사람이 직접 지정한 값이고 도구가 자동으로 채우지 않습니다. 그래서 이 페이지의 모든 수치는 **담당자 기준**입니다.

## 산정 방법

| 항목 | 기준 |
| --- | --- |
| PR 대상 | `OneOrThree/phone`의 머지된 PR 666건 중 변경 파일 정보를 받은 665건 |
| PR 담당자 | GitHub assignee. 담당자가 지정되지 않은 16건은 PR 작성자로 대체했습니다 |
| 영역 귀속 | PR이 바꾼 파일 경로로 판정 — `back/` → 백엔드, `app/android/`와 네이티브 모듈의 `android/` → 안드로이드, `app/ios/`와 모듈의 `ios/` → iOS, 나머지 `app/` → 앱(RN), `docs/` → 문서, `.github/`·`observability/`·`loadtest/`·`scripts/` → 인프라·CI |
| 다중 영역 PR | 백엔드와 앱을 함께 고친 PR은 두 영역 모두에 1건으로 셉니다. 그래서 영역 합은 전체보다 큽니다 |
| 지라 대상 | `GROMO` 프로젝트 전체 1,278건 중 담당자가 지정된 1,178건. 미지정 97건은 분모에서 뺐습니다 |
| 기준일 | 2026-08-24 스냅샷 — 소스 저장소는 이 사이트의 빌드 환경에 없으므로, 수치는 커밋된 스냅샷이고 갱신 시점을 함께 적습니다 |

퍼센트의 분모는 각 영역의 팀 전체 건수입니다. 라인 수는 보조 지표로만 씁니다 — 자동 생성 파일과 lock 파일이 섞이면 라인 수가 먼저 왜곡되기 때문입니다.

## 이 숫자의 한계

- PR 건수는 작업 난이도를 반영하지 않습니다. 한 줄짜리 hotfix와 3주짜리 재편이 같은 1입니다.
- 담당자가 없던 PR 16건은 작성자로 대체했으므로, 그만큼은 여전히 작성자 기준입니다.
- 지라 미지정 97건은 분모에서 뺐습니다. 이 티켓들이 특정 사람에게 몰려 있었다면 비율이 달라집니다.
- 한 PR에 두 사람이 붙어도 담당자는 첫 번째 한 명만 셉니다.
- 리뷰 기여(코멘트·승인)는 이 산정에 없습니다. 별도 축으로 추가할 후보입니다.
