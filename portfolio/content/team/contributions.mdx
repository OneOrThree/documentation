## 산정 방법

팀·역할 페이지의 도넛은 감이 아니라 저장소 이력에서 나온 숫자입니다.

| 항목 | 기준 |
| --- | --- |
| 대상 | `OneOrThree/phone` main 브랜치, 파일 변경이 있는 커밋 849건 |
| 커밋 = PR | 이 저장소는 squash 머지 전용이라 main의 커밋 1개가 PR 1개이고, 작성자 귀속이 머지 커밋으로 흐려지지 않습니다 |
| 영역 귀속 | 커밋이 변경한 파일 경로로 판정 — `back/` → 백엔드, `app/android/`와 네이티브 모듈의 `android/` → 안드로이드, `app/ios/`와 모듈의 `ios/` → iOS, 나머지 `app/` → 앱(RN), `docs/` → 문서, `.github/`·`observability/`·`loadtest/`·`scripts/` → 인프라·CI |
| 다중 영역 커밋 | 백엔드와 앱을 함께 고친 커밋은 두 영역 모두에 1건으로 계산합니다. 그래서 영역 합은 전체보다 큽니다 |
| 지라 발행 | `GROMO` 프로젝트 전체 이슈 1,278건을 발행자(reporter)로 나눔 — 이슈 유형(작업·버그·에픽) 무관 전체 집계 |
| 기준일 | 2026-08-18 스냅샷 — 소스 저장소는 이 사이트의 빌드 환경에 없으므로, 수치는 커밋된 스냅샷이고 갱신 시점을 함께 적습니다 |

퍼센트의 분모는 각 영역의 팀 전체 커밋 수입니다. 라인 수는 보조 지표로만 씁니다 — 자동 생성 파일과 lock 파일이 섞이면 라인 수가 먼저 왜곡되기 때문입니다.

## 진행 중 — 아직 main에 없는 것

- **애플워치**: `GromoWatch` 워치 타겟은 wake 측정 스파이크로 신설된 상태이고(GROMO-1596) 아직 main에 머지되지 않았습니다. 머지되면 이 페이지에 영역으로 추가합니다.
- **안드로이드 M2·M3**: 위 표 참고.

## 코드 밖의 기여

커밋으로 잡히지 않는 축도 있습니다.

- **워크스페이스 셋업**: 지라·슬랙·깃허브 초기 세팅과 협업 프로세스 설계(`GROMO-36`·`GROMO-46`·`GROMO-47`·`GROMO-55`·`GROMO-56`) — 팀이 굴러가는 판 자체를 깔았습니다.
- **연구 노트**: 이 사이트의 [연구 노트 29편](/research)이 그 과정의 기록입니다.

## 이 숫자의 한계

- 커밋 수는 작업 난이도를 반영하지 않습니다. 한 줄짜리 hotfix와 3주짜리 재편이 같은 1입니다.
- 페어로 작업하고 한 사람이 커밋한 경우 그 사람에게 귀속됩니다.
- 지라 발행 건수는 이슈 유형을 가리지 않은 전체 집계입니다. 한 줄짜리 하위 작업과 설계 문서급 티켓이 같은 1입니다.
- 리뷰 기여(코멘트·승인)는 이 산정에 없습니다. 별도 축으로 추가할 후보입니다.
