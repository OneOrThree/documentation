## 무엇을 누구에게 귀속했나

GitHub `OneOrThree/phone`의 **머지된 PR <Contrib path="overall.merged" />건**을 조회했다. 각 PR의 `assignees`와 변경 파일 목록을 GitHub GraphQL API에서 끝까지 페이지네이션했고, 파일이 100개를 넘는 PR도 남은 페이지를 모두 읽었다. 가장 늦게 머지된 PR의 시각은 <Contrib path="asOfKst" />다.

**사람을 정하는 유일한 필드는 PR의 assignee다.** 커밋 author, PR author, 공유 AI 계정, 코드 줄 수는 사람별 기여에 쓰지 않았다. assignee가 없는 <Contrib path="overall.areas.overall.unassigned" />건은 누가 작성했든 **미배정**으로 따로 남겼다. 현재 데이터에서 복수 assignee와 세 팀원 외 assignee는 없었다.

| 기준 | 처리 |
| --- | --- |
| 전체 대상 | 머지 PR <Contrib path="overall.merged" />건. 열린 PR, 닫혔지만 미머지인 PR 제외 |
| 사람별 분모 | assignee가 있는 <Contrib path="overall.areas.overall.total" />건. 미배정 <Contrib path="overall.areas.overall.unassigned" />건 제외 |
| 영역 | PR의 변경 파일 경로로 판정. 한 PR이 여러 영역을 바꾸면 각 영역에서 1건씩 계산 |
| 백엔드 | 옛 `back/`과 현재 `server/` 서비스 코드. `server/scripts/`·`server/docs/`는 각각 인프라·문서로 분리 |
| 앱 | `app/`의 React Native 코드·자산·설정. 경로에 `ios`·`android`가 들어가는 네이티브 파일은 각 네이티브 영역에 배정 |
| 인프라·CI | `.github/`, `observability/`, `loadtest/`, `scripts/`, `server/scripts/`, 루트 `docker-compose*` |
| 문서 정본 | `docs/`, `server/docs/` |
| 재현 | 저장소의 `portfolio/scripts/sync-contributions.py`가 GitHub assignee와 전체 파일 목록을 다시 조회해 `src/data/contributions.json`을 생성 |

퍼센트의 분모는 **각 영역에서 assignee가 확인된 PR 수**다. 여러 영역을 함께 바꾼 PR은 여러 표에 들어가므로 영역 합계는 <Contrib path="overall.areas.overall.total" />건보다 크다. 지정한 영역 밖의 파일만 바꾼 PR은 전체 집계에만 들어간다.

## 규모 가중 — PR 한 건의 크기를 반영

건수만 세면 한 줄 수정과 수천 줄 리팩토링이 같은 1건이 된다. 그래서 같은 assignee 귀속 규칙 위에서 **PR이 바꾼 줄 수**(추가+삭제)를 함께 센다. 사람을 정하는 필드는 여전히 assignee 하나다.

| 기준 | 처리 |
| --- | --- |
| 제외 파일 | `.json`(락파일·맵 데이터·스키마 덤프), `.lock`, `.pbxproj`, `.gypi`, 이미지(`.svg`·`.png`·`.jpg`), `.drawio`, `gradlew` — 사람이 손으로 쓴 변경이 아니거나 한 번에 수천 줄이 생기는 파일 |
| 포함 파일 | 소스·테스트·마이그레이션 SQL·설정·문서(`.md`·`.html`). 테스트와 문서도 작업이므로 뺐다 넣었다 하지 않는다 |
| 영역 배정 | 파일 단위. 한 PR의 줄 수가 파일별로 각 영역에 나뉘어 들어가므로 영역 합계가 전체와 맞는다 |
| 이상치 | 전체 줄 수 외에 **PR당 2,000줄 상한**을 둔 값을 따로 보인다. 대형 PR 몇 건이 비율을 좌우하는지 확인하기 위해서다 |

## 이 사이트의 문서 — 작성자 기준

기획 문서·ADR·리서치·운영 기록은 phone 저장소 밖의 이 사이트에도 쌓인다. 이 사이트 저장소의 PR은 대부분 assignee가 비어 있어 위 규칙을 그대로 쓸 수 없다. 대신 각 문서 frontmatter의 **`author`**(그 문서를 책임지는 사람으로 적은 이름)로 센다. 작성자가 팀 이름이거나 비어 있는 문서는 넣지 않는다. phone 저장소의 `docs/`(PRD·정책·설계)는 이미 위 **문서 정본** 영역에 들어 있다.

<DocumentTable />

문서 수와 줄 수는 분량이지 품질이나 의사결정 기여가 아니다. 광고 집행·사용자 인터뷰·외부 커뮤니케이션처럼 저장소에 남지 않는 일은 이 페이지의 어떤 표에도 들어가지 않는다.

## 이 수치로 알 수 없는 것

PR 한 건은 작업 시간·난이도·리뷰 기여와 같지 않다. 건수 표에서는 한 줄 수정과 여러 주에 걸친 리팩토링이 같은 1건이고, 줄 수 표에서는 어려운 한 줄과 기계적인 수백 줄이 줄 수대로 계산된다. 두 표를 함께 보는 이유다. 한 PR을 함께 만든 사람도 assignee 한 명에게만 들어간다. 커밋과 작성 계정에서 실제 작업자를 역추정하지 않는다. 따라서 이 표는 **기록된 작업 책임의 분포**이며 개인의 노동량이나 성과 점수가 아니다.
