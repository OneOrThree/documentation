## 오너십

역할은 직책이 아니라 **책임 결과물**로 적는다. 아래 첫 표는 2026-09-23의 2.0 작업 기록과 담당 티켓에서 확인한 범위다. 한 티켓의 담당자는 영구 독점권이 아니며, 동시 작업은 PR 범위로 구분한다.

| 팀원 | 2.0에서 확인한 책임 범위 | 최근 근거 |
| --- | --- | --- |
| 조재영 | 팀장 · 제품/서버 정책 결정 · Data/Business/Realtime/Notification 경계 · 서버 리팩토링·검증 조정 | Sprint 15 결정 장부의 재화·집중·실시간 정책, 09-23 서버 전용 DTO·오류 경계 PR #943~#956 및 후속 #959~#965 |
| 권태화 | 서비스 인프라·배포·관측 · 모바일 작업 | 09-22 인프라·배포 티켓 담당 배정, dev 배포/시크릿·Datadog 경로, 앱 차단 기능 티켓 담당. 티켓 배정은 구현 완료와 구분 |
| 안수빈 | 앱 제품 구현 · iOS 네이티브 · 디자인·마케팅 | 같이숲 2.0 앱 화면, iOS Screen Time, 온디바이스 캐릭터 작업. 09-19 방문자 열람 범위 제안은 서버 티켓 GROMO-1937로 연결 |

8월 중간심의 시점에는 조재영의 백엔드 테스트 **1,819건 통과·7건 제외·실패 0, 라인 커버리지 89.4%**, 권태화의 **k6 부하 실험 6회**, 안수빈의 앱 테스트 **1,855건 통과와 App Store 1.0.0 출시**를 기록했다. 이는 2.0의 현재 테스트 규모나 출시 상태가 아니다.

담당자 기준 PR·지라 비율은 [기여 분담 상세](/team/contributions)에 있다. 백엔드 87.3%, 인프라·CI 73.6%, 문서 정본 71.9%는 **2026-08-24까지의 PR 누적 비율**이다. 지라 완료 티켓은 2026-09-21 조회분이다. 9월의 2.0 작업 분담을 이 비율로 설명하지 않는다.

오너십은 "혼자 만든다"가 아니라 **"바꿀 때 리뷰를 받아야 하는 사람"** 을 뜻한다. 백엔드와 앱을 함께 고친 PR은 양쪽 담당자가 본다.

## 2.0 작업의 경계

- **제품 판정**: 재화 귀속, 적립일, 강퇴 정산처럼 정책을 바꾸는 선택은 결정 장부와 기능 정책에 남긴다. 구현자가 리뷰 중 발견한 결함은 정책 변경과 구분한다. [2.0 재화 결정](/adr/adr-035-village-economy-boundaries)
- **서버**: Data가 원장·멤버십·정산의 최종 상태를 갖고, Business가 공개 API와 화면 조합을 맡는다. Realtime의 presence는 최종 권한이 아니다. 알림은 신·구 발송 경로를 구분한다.
- **앱**: 서버 응답을 화면에 연결하고 네이티브 측정·배포를 담당한다. 2.0 TestFlight 업로드는 앱스토어 공개 출시와 별개다. 푸시·딥링크는 후속 티켓 GROMO-2090·2091로 추적한다.
- **인프라**: 배포 시크릿 주입, 서비스 기동, 관측·CI의 검증 경계를 맡는다. 09-23 dev 배포 문제는 배포 준비 기록으로 남기고 제품 기능 완료로 세지 않는다.

근거: `phone/doc/parallel/sprint15-2026-09-20/decisions.md`, `phone/logs/09-22.md`·`09-23.md`, `phone/logs/ponytail-server-refactor-2026-09-23.md`, `phone/docs/engineering/testflight/2026-09-23-ios-release.md`. 로그는 비공개 작업 기록이므로 이 사이트에는 정책·상태만 옮긴다.

## 경계 계약

서버와 앱, 앱과 OS 네이티브 계층이 만나는 지점에서 오가는 것은 다음 넷이다. 이 밖의 방법으로 서로의 내부를 읽지 않는다.

1. **공개 REST와 에러 봉투** — 앱이 분기하는 에러 코드는 `<Domain>ErrorCode`에 있는 것만 쓴다. 404 세 갈래·409→400처럼 구버전 앱에 영향을 주는 계약 변경은 호환 분기와 배포 순서를 함께 설계하고 앱 티켓과 짝짓는다. [ADR-005](/adr) · [계층 리팩터링 기록](/research/backend-layering-refactor)
2. **서버 최종 판정** — 리그 정산·재화·그룹 내기처럼 장애 비용이 큰 경로는 금액과 판정을 서버가 정한다. 멱등키, 유저 행 락, 마이그레이션, 회귀 테스트를 같은 PR 묶음에 둔다. [재화·정산 무결성](/research/money-integrity)
3. **OS 네이티브 측정과 서버 정합성의 분리** — 스크린타임 제어와 측정은 iOS·Android 네이티브 계층이 담당하고, 서버는 세션·랭킹·그룹·재화의 최종 정합성만 관리한다. 네이티브 모듈이 앱에 노출하는 JS 계약은 스크린타임 설계서에 있다.
4. **날짜 축** — 저장은 UTC, "오늘" 버킷은 쓰기는 서버 country-zone·조회는 클라 date다. 서버 코드의 `LocalDate.now` 호출은 0건을 유지한다. [타임존 버킷 전쟁](/research/timezone-wars)

## 협업 방식

- 기획 → PRD·HLD·LLD → Jira 티켓 → PR → 자동 테스트 → 일별 로그의 **추적 사슬**을 유지한다. 지라 티켓은 도메인·Label·Epic·fixVersion 4축으로 분류한다.
- 사용자 경험과 운영 리스크를 같은 우선순위로 검토하고, 정식 출시 전 실기기·부하·개인정보 게이트를 통과한다.
- 팀이 Claude 계정을 공유해서 쓰므로 커밋 작성자는 담당자와 다를 수 있다. 기여는 커밋이 아니라 PR·지라 담당자로 센다.

## 문서 규칙

- 결정은 [설계 결정](/adr)에 남긴다. 뒤집힌 결정도 지우지 않고 상태만 바꾼다.
- 기능 문서는 `prd·policy·IA·HLD·LLD` 5종 세트로 두고, 정책이 충돌하면 `policy.md`가 정본이다. 팀 전체 규약은 `docs/conventions/`에 둔다.
- 명세와 위키가 어긋나면 [명세](/spec)가 이긴다.
- 측정한 것은 숫자와 재현 명령, 기준일을 함께 남긴다.
